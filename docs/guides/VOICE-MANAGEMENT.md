# 语音管理与云端/本地引擎边界（2026-11-08）

本资料最初记录语音管理解除QQ桥接依赖；下方新增火山语音开发状态。离线测试不代表任一真实引擎或QQ发送已验收。

## 火山语音 2.0（开发中，尚未实机验收）

语音页可单独输入 API Key，选择“火山语音 2.0 · 小何”。密钥不回显，保存在配置根 `state/volc-voice-keys` 的独立受限文件中；替换密钥会保留旧文件用于恢复。“选择火山并启用合成”会选择云端路线并启用 TTS，不启动旧语音包；发送总闸和工具开关仍由用户显式设置。未明确设置的发送总闸保持关闭。独立保存后，页面核对保存前后内容戳并尝试三方合并主设置草稿；没有冲突时自动刷新版本戳。若同时改动同一字段或配置再次变化，保留草稿并提示先复制未保存内容，再重新读取（重新读取会替换草稿）。手动自检会向火山发送测试文字并消耗额度；所有文字合成的 dry-run 只检查参数，不请求任何语音服务，也不会生成音频。provider 固定小何和 `seed-tts-2.0`，单次最多120字；新云端 provider 不参与自动换路。音频只有在收到官方 `20000000` 合成结束帧，且 RIFF 总长度、音频块长度与完整内容一致时才保存；缺结束帧和未知长度 WAV 均拒绝。[官方 V3 HTTP 文档](https://docs.volcengine.com/docs/DoubaoVoice/HTTPChunkedSSEUnidirectionalStreaming-V3)说明流式 WAV 可能多次返回头部。当前支持合并各自完整、格式完全一致的 PCM WAV 段（16字节 fmt、24kHz、无附加块、样本对齐）；未知长度、附加块、压缩格式或格式不一致时安全拒绝。仅离线夹具验证，官方实际响应的兼容性待验。管理自检读取最新配置；QQ桥接读取启动时配置，修改选择或密钥后须重启桥接。

火山每次请求前在 `state/volc-voice-budget.json` 预留一次和请求字符，所有进程共用：最多每分钟2次、每小时10次、每UTC月100000字；配置较低发送频率或月额度时采用较低值。火山设置卡可输入并保存1–100000的本机UTC月上限，显示当前生效值；该值单独存储，不改旧云包额度；保存时若旧云额度更低，新值会被收紧到该旧上限，防止后续移除旧上限时额度意外增加。这不是云端余额。失败、取消和不确定结果不退回预留。此为保守本机硬限，不是火山账单或实际剩余额度，使用情况需在火山控制台核对。账本损坏、时钟回拨或锁未释放时拒绝调用，保留账本和锁并检查；禁止删除账本绕过额度。旧语音包的用量日志不能代表火山直连。

容器网关可将 `socialV2.voice.recordTransport` 显式设为 `base64`：经过音频检查和大小限制后以内联数据交给网关。火山密钥读取和内联传输要求系统支持 `O_NOFOLLOW`，不支持时明确拒绝，原 voxd 路径仍可用。默认值为本机路径，沿用旧行为；本选项需要重启桥接，固定版 NapCat 源码支持该输入，但真实发送未验。切回旧云服务可在语音页选择“使用原云端服务”，或激活已安装的旧云包；后者会原子保存 `cloudProvider=voxd` 并保留火山配置。切换后重启 QQ 桥接；旧桥接若仍持有火山配置会拒绝新的火山请求，已发起的请求可能继续完成。共享锁覆盖旧包激活、语音管理选择及火山、旧 voxd 云请求发起；桥接、Host 自检、旧云试听和桌宠旧云请求均核对选择版本，切换或切回后旧桥接需重启。桌宠暂不支持火山直连，选择火山时降级文字并返回明确错误，真实桌宠界面的提示仍待验。本版设置存储、桥接、自愈、恢复和启动配置写入也使用该锁；通用入口不能直接修改服务选择、端点或语音频率/月额度，应通过语音管理操作。若需自定义端点，先停止相关 Host、桥接和语音调用，备份配置后手工编辑，再重新启动；手工编辑、旧版本进程或其他不遵守该锁的工具不能安全并发写配置；为兼容旧客户端，无版本戳的全量保存仍可能覆盖其他非语音字段的并发修改。事务拒绝符号链接形式的 QQ 配置或状态目录；若现有安装使用链接，应先停相关进程、备份并核对路径后再迁移，不能自动覆盖。旧包激活前的配置保存在 `state/voice-activation-backups`，可能包含敏感信息；回退时保留密钥目录、备份和预算账本。

## 资料与结论

| 一手资料 | 核对内容 | 对当前项目的意义 |
| --- | --- | --- |
| [Node24 HTTP生命周期](https://nodejs.org/docs/latest-v24.x/api/http.html#serverclosecallback) | 独立server需要自行管理关闭和活跃连接 | 复用DSH现有受保护路由，无需新增管理端口；语音模块不能关闭共享Host服务器 |
| [Node24文件系统](https://nodejs.org/docs/latest-v24.x/api/fs.html) | wx排他创建、EEXIST处理；先检查再写存在竞态 | 共享管理写操作需明确归属，不能靠两个实例各自的Map假设独占 |
| [Node24子进程](https://nodejs.org/docs/latest-v24.x/api/child_process.html#child_processspawncommand-args-options) | detached/unref进程可能在父进程退出后继续；发送信号不等于确认退出 | 管理接口可用不代表引擎生命周期已经受控；现有Windows脚本不能冒充Mac支持 |
| [GPT-SoVITS维护者API实现](https://github.com/RVC-Boss/GPT-SoVITS/blob/main/api_v2.py) | 原生合成路由为/tts，需文字/语言/参考音频等参数 | 不能只把地址替换进当前/v1/speak/file客户端；需要本地适配层 |
| [火山官方HTTP单向流式TTS](https://docs.volcengine.com/docs/doubao-voice/unidirectional-streaming-text-to-speech-http?lang=zh) | 官方/api/v3/tts/unidirectional有独立认证、req_params及音频流协议 | 云端也需要provider适配层；不能在管理解耦时擅自迁移旧AppID/AccessKey配置 |

Node24文档同时经Context7核对。上述latest/main链接会变化，实际接入时应按所选引擎版本和账号资源再核对。

## 当前实现和后续配置

现有`src/voice-tts.js`面向voxd包装协议：`POST /v1/speak/file`输入文字/音色，返回WAV字节与可选时长/缓存头；Host自检还读`GET /v1/health`。`src/voice-packs.js`保存包目录、安装进度与云端参数，独立于QQ消息泵。原Host仅代理3100，所以QQ停止时连管理页也失败。

采用Host直接承载共享管理模块：列表/配置/状态在QQ关闭时仍可用；概览和独立启停也迁入。旧QQ控制台复用该模块，保留原认证；QQ对外发送/语音库的准入仍由桥接负责。备选独立常驻管理服务虽可集中所有权，但新增端口、鉴权、进程监督和升级成本，当前收益不足。

后续选择本地时核对Mac架构、推理运行时、模型与音色许可、原生API及适配层；选择云端时核对认证代际、资源/音色、费用/额度、隐私及适配层。引擎选择不会改变本次独立管理入口。旧离线包有Windows/NVIDIA依赖，在Mac不应自动下载或尝试运行。


### Mac火山小何的已验入口

在“火山语音2.0 · 小何”卡片自行输入新版API Key并选择启用合成；私聊使用前打开页顶语音总闸与工具开关，保存后完整退出DSH再打开。独立NapCat容器需显式`socialV2.voice.recordTransport=base64`；默认仍为宿主路径。当前已验证小何2.0、仅主人、2条/分钟、10条/小时、单次最多120字及主人手机播放。自检会合成“语音自检”且消耗本机预留；只自检不发QQ。火山真实流式WAV长度未知时，收到官方完成帧才修复；缺结束或损坏格式不会落盘。失败不自动重试、不切服务，预留不清零；本机账本不是火山账单。
