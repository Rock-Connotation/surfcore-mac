# 本地 Agent 开发提示词：macOS、共享核心、ASR 与 B站

使用方式：在含本交接提交的 `surfcore-tooling-docs` 工作树打开本地 Agent，将下面整段文本作为任务发送，或让 Agent 读取并执行本文。
设计正文在本地 [docs/design/macos/](../design/macos/README.md)，被 Git 忽略；只有本文件而没有设计原稿的克隆不具备完整输入。

```text
你是 SurfCore macOS 的开发 Agent。请根据本仓库已归档的 macOS 技术设计，完成首期实现、必要回归、本地提交和可复现的验收交接。请实际开发，不要只输出计划；在当前授权范围内按依赖连续推进，无需每完成一步询问是否继续。

一、目标与范围

交付在目标 Mac 的真实 DSH 中可运行的 SurfCore：统一人格、关系、记忆和生活状态；共享本地 ASR；B站作为首个完整接入渠道。QQ bridge 关闭时，核心维护和 B站经历进入长期记忆的链路仍能工作。

首期本地 ASR 必须实际可用：运行时、模型准备、完整音轨、转写时间轴、覆盖范围、取消/恢复、诊断和真实中文样本均属于交付。空接口、仅调用平台字幕或 QQ 语音识别不算完成。

保留现有预算、静默、账号隔离、权限、隐私 scope、遗忘规则、Windows 兼容路径和用户数据。QQ、抖音、本地渠道预留共享契约，不扩大为同时完成全部平台；TTS、桌宠和 QQ 未配置不能阻断首期 B站路线。

1. 先读 AGENTS.md；严格依次读 docs/ROADMAP.md 顶部路线守则、docs/HANDOFF.md，带当前任务问题查 docs/PITFALLS.md，再读代码。补读 docs/guides/DEVELOPMENT-TOOLS.md、docs/guides/ERROR-REPORTING.md、docs/RELEASE.md 和 docs/COORDINATION.md。
2. 运行 git status --porcelain、git worktree list、git log --oneline -5，记录实际分支/HEAD/改动归属。不要覆盖或提交别人改动，不在别人工作树里切分支、stash、reset 或 clean。
3. 本交接来源是 docs/tooling-macos 分支，设计源码基线是 v0.8.8 / 0deb8261afe4c31b3127759ee4de36a1439cf422。开发起点应包含本提示词和工具指引；不要 checkout 回旧基线丢掉交接内容。核对分支是否已推进或已被合并。
4. 若 dev 已存在且已包含交接，按仓库规则从 dev 新建独立工作树。若仍没有 dev，本任务允许从已核验的 docs/tooling-macos HEAD 新建 feat/macos-implementation 与同级 surfcore-macos-implementation 工作树；记录这一局部基线选择，不创建假的稳定线或擅自合并主工作区。名称已占用时先核对其归属，为本会话选未占用名称。
5. docs/design/、docs/research/ 和 _backups/ 不随 Git worktree/clone 携带。在来源工作树确认 docs/design/macos/README.md、01—07 分册及完整合并版均存在，再复制整个 macos/ 到新工作树同名目录。目标已有文件时先比较并保留差异，不覆盖另一版本。按需携带本地工具盘点；测试日志可引用来源工作树，无需复制用户运行数据。
6. 在新工作树更新自己的 COORDINATION 行。后续写操作都在本会话工作树内；所有备份与资料继续遵守仓库忽略策略。

按 docs/design/macos/README.md 的阅读顺序读取：

- 04-bilibili-adapter.md：选 P、完整媒体、字幕/ASR/视觉、理解与互动回执。
- 05-implementation-plan.md：WP0—WP5 依赖、修改文件地图与通过条件。
- 06-acceptance-and-migration.md：编号用例、实机矩阵、迁移和回滚。
- 07-evidence-and-decisions.md：决策依据、源码定位与未验证假设。

完整合并版用于连续阅读，分册用于实现定位。文中的建议文件/API 名不是已有实现；核对当前源码的读者、调用链与数据所有者。设计里的外部版本、API 和性能陈述，使用前从对应锁定版本源码/官方文档复核。

本任务将设计的首期目标作为实施依据，但不把设计自述当作验收结果。发现设计与当前源码有差异时，记录差异及兼容修法；普通实现取舍自行分析并推进。若改变业务目标、权限/隐私边界、迁移语义或核心契约，先准备具体取舍和建议，待用户决策；继续不依赖该决策的工作。

ROADMAP 仍有历史“仅 Windows、跨平台以后”的范围说明。完成 WP0 核实后、写功能代码前，将本次已要求的 macOS 首期目标、依赖与验收边界同步到路线图，标清设计目标/实现进度/已验收状态，保留 Windows 兼容要求。

四、按依赖连续实施

WP0：记录实际系统、物理/进程架构、Rosetta、DSH 分发/版本/App/profile/DSH_HOME，以及实际执行的 Node/FFmpeg/FFprobe/浏览器。建立隔离数据根与测试账号边界，确认“哪个宿主、哪个 profile、哪个 Node 在执行哪份代码”。不要套用旧 Windows 交接中的端口、路径和版本。

先复核 docs/cases/2026-11-06-development-tools-and-macos-design.md 中的门禁失败：路径 /var 与 /private/var、Windows CRLF/chcp/PowerShell、依赖真实 config.json 的用例、插件更新器 r.changelog 缺失等。该记录是历史运行结果，不是当前结果。先正确安装锁定依赖并理解 postinstall；逐项区分环境前置、测试缺陷、现有产品缺陷和新增回归。修复首期所需的基线/测试阻塞并满足当前平台适用门禁，再进入新功能。保留 Windows 测试与相应验证责任；不能靠删用例、降断言或把未执行记作通过来变绿。

WP1：增量复用现有 character-persona、persona-layers、memory-card、purpose-engine，建立统一上下文、ExperienceEvent/去重、Host 唯一记忆维护者、角色级生活状态和 characterEpoch/活动归属。避免同一角色产物被 Host 与旧 bridge 定时器同时写入。

WP2：统一运行时选择，使调度器子进程与 Agent 命令同源；补齐 .app/Unix Node、Finder 环境、中文/空格路径、浏览器与媒体工具发现、进程所有权、退出/重载/休眠恢复及分层诊断。只清理本实例拥有的子进程。WP1 与 WP2 可以独立推进，是否委派以收益和工具实际能力为准。

WP3：在 WP1 契约和 WP2 运行能力上实现共享本地 ASR。优先验证设计中的 whisper.cpp 固定版本、原生 Metal/CPU 与多语言 small/base 候选；用目标机器样本决定默认模型。任何替换需保留设计契约并记录实测理由。落实语言显式传递、模型资产校验、规范化、原始毫秒时间轴、长作业分块/合并、完整覆盖、并发限制、缓存隔离、取消与重启恢复；本地失败不能自动上传音频到云端。

WP4：B站完成 p/page/cid 一致解析、DASH/durl 完整获取、字幕所属 cid 验证、共享 ASR 接线、视觉与结构化 debrief、watch-history 元数据、经历入库和下一会话召回。账号鉴权留在渠道，ASR 只接收媒体资产。重试不重复外发；回执区分成功、确定失败和结果未知。

WP5：实现自包含插件制品、安装身份、明确升级所有者、fork 来源、跨平台更新与迁移回滚；先在隔离副本演练。核对完整仓库相对引用不会使最终安装包依赖包外 src。形成真实支持范围和发布交接；本任务不执行版本号变更、打 tag、推送或发布。

每个工作单元先给出“现象/目标 → 机制或根因 → 影响面 → 两条路线的收益/成本/风险/回滚 → 选择 → 验证”，然后实施最小完整链路。不要把全仓重构作为前置，也不要交付未接入实际调用点的孤立模块。

五、工具与协作

六、授权与阻塞边界

本任务允许项目代码/测试/文档开发、隔离环境验证、必要项目依赖和模型资产准备，以及按功能粒度本地提交。依赖/模型优先复用，确需下载时说明来源、版本、体积及目标资产目录；不污染全局环境或自动启用付费/云端替代。

真实 DSH profile 安装/配置修改、重启共享运行时、真实账号外发/付费调用、用户数据迁移和不可恢复操作，先核对用户是否已授权该对象与动作；缺少时先准备可审阅的改动、影响与恢复步骤，再申请最小必要授权。已有授权范围内不重复询问。扫码、系统权限或缺少目标实机确需人工时，只阻塞相关验收项，继续独立实现与离线验证。

所有 probe、setup、启动/重启脚本按仓库规则先说明目的、预期与失败后果。用户配置、会话、角色、模型和缓存按所有权处理；修改前备份，删除走隔离。密钥、Cookie、令牌和带签名媒体 URL 不进代码、日志、截图或回复。

七、验证和完成条件

按 06 的编号逐项记录：目标提交/环境、输入、预期、实际、状态和证据路径。每批执行适用检查：至少 npm run test:audit；协议/桥接加 npm run test:regressions；插件变更执行对应插件测试及 npm test --prefix plugins/surfcore。新增失败路径断言 code 和 hint；前端展示失败与下一步，不得只写日志。

实际证明以下关键链路：
- Finder 与终端启动时执行同一套预期运行能力；空格/中文/自定义数据根正常。
- 真实中文无字幕样本取得并处理到尾部；多 P、多分段、截断、静音、长音频、取消和重启的状态与覆盖正确。
- QQ bridge 关闭后，B站账本 → 经历 → 统一记忆 → 下一会话读取闭环成立。
- 角色切换期间旧作业不污染新角色；重复事件/重试不重复记忆或外发。
- 迁移/更新/回滚保留角色、记忆、账号绑定、模型和更新后新增数据。
- 真实界面中成功与失败都可见、可操作；API/fixture 只能证明对应层级。

实机不足的 Intel、Windows 或其他矩阵项如实标记未验证，不声称支持；缺少真实 ASR/目标 DSH 验收时不能宣告首期全部完成。将可独立完成的部分推进到可审阅状态，留下具体缺项与最小补验步骤。

八、提交与持续交接

按功能拆中文 commit，只暂存明确文件/片段，提交前检查实际 staged diff，保留 hooks。不要把机器资料、设计原稿、凭据、模型和大音频强制入库。正常功能批次以对应检查通过为前提；遗留失败保留原始证据，不改写成通过。没有 push/release 授权，不推远端、不改版本号、不打 tag。

每批更新 docs/HANDOFF.md、自己的 COORDINATION 状态、适用的 ROADMAP/PITFALLS 和 docs/cases/ 索引；case 写完整逻辑、失败路径、回滚与 docs/RELEASE.md 要求的发布交接块。以 05 工作包和 06 编号记录完成/待验/阻塞，不再建一套互相漂移的进度账本。

收工说明：完成哪些实际链路、提交 SHA、验证命令与结果、实机证据位置、需要重启谁、未验证项和下一步。当前任务未完成且还有可推进项时继续执行，不以“计划已写好”结束。

现在开始：完成开工核对、设计阅读与独立工作树登记，用简短进度说明报告真实基线和第一项可执行工作，然后立即进入 WP0；缺少输入只暂停依赖它的动作。
```
