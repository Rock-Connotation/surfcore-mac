## 现象与环境

用户希望 QQ 中的伙伴使用火山语音合成 2.0 和“小何 2.0”音色发送语音。Mac 使用官方 DSH 和独立 NapCat Docker；原有语音包依赖 Windows 运行时，无法在该环境直接启动。用户已开通火山语音合成服务并购买字符包。

## 根因

原合成客户端使用 voxd 的 `/v1/speak/file` 和 `/v1/health`，不兼容火山官方接口。QQ 桥接发送的是宿主机文件路径，独立容器不能直接读取该路径。旧语音包的用量日志也不能反映直接访问火山的调用。

## 完整逻辑

1. **链路**：语音设置页经 DSH Host 写入配置和受限凭据；QQ 桥接按原有会话及目标权限处理语音，火山 provider 合成音频，选定的容器传输方式将音频交给 NapCat。原 voxd 线路仍保留。
2. **机制**：火山 provider 显式配置后才使用；API Key 保存在权限受限的独立本机文件，属于明文文件而非系统钥匙串。火山失败不自动换路。语音数据经音频和大小检查后才进入发送链路。
3. **影响面**：Host 管理、自检、QQ 桥接及 NapCat 均受影响；涉及账号密钥、本机音频和可能计费的云请求。文字发往火山进行合成；原有目标白名单和语音频率规则不得放宽。
4. **取舍**：进程内 provider 复用现有管理及合成调用，减少独立常驻服务；独立 voxd 包装服务可减少既有调用方改动，但增加进程、端口和生命周期成本。采用前者，保留旧线路作为回滚选项。
5. **生效与重启**：源码变更尚未安装到常用 DSH；安装后需按实际 Host 与桥接读配置的生命周期重载或重启。具体安装、数据备份及回滚须在实装前按当前状态核对。
6. **验证**：规则补修后，隔离工作树在官方 Node 24.21.0 下执行 `npm run test:audit`（187/187）、`npm run test:regressions`（17 项通过）、`npm --prefix plugins/surfcore test`（退出码 0）。定向测试覆盖分片、预算、双向切换、配置事务、草稿及规则部分更新。未做真实云、QQ或宿主界面验收。
7. **回滚与残余**：保留原配置、凭据文件、音频与用量账本；切回旧 provider 或恢复旧程序时不能覆盖新产生的数据或清空额度。当前没有真实火山合成、实际账单、音质或 QQ 手机收听证据。

## 火山切回旧云包

独立复核发现旧包激活原先只改 `route=cloud`，保留 `cloudProvider=volc`，导致界面称旧包已启动，随后仍可能使用火山并付费。旧云包激活现先在共享预算锁内备份配置，再原子写入 `route=cloud`、`cloudProvider=voxd` 并沿用旧包激活时启用 TTS 的行为；火山密钥引用与限额不删除。备份位于 `state/voice-activation-backups` 的受限文件，可能包含配置中的敏感信息，不应公开或擅自删除。

火山请求的配置复核、预算预留和请求发起，与旧包激活及语音管理接口的路线选择共用跨进程锁；本版内置的通用设置、桥接、自愈、配置恢复与启动初始化已接入相同事务锁；通用入口禁止直接更改 provider、路线或选择版本。手工编辑、旧版本进程及其他不遵守锁的程序仍可绕过该保障，应避免并发修改；为兼容旧客户端，无版本戳的全量保存仍可能覆盖非语音选择字段的并发修改。旧桥接缓存仍选火山但磁盘已切换时，返回 `VOICE_VOLC_CONFIG_CHANGED`，要求重启桥接，不发火山请求。已经发起的请求仍可能在切换后结束，预留不会退还。配置损坏、锁被占用或原子写失败返回可行动错误，不报告切换成功；若已启动旧服务，需核对状态再操作。离线覆盖旧包激活保留火山配置、备份、旧桥接拒绝、旧云自检和写入失败。Windows实际运行及真实火山/QQ仍未验。

## 双向切换和自检补修

复核发现从旧 voxd 切到火山后，已运行桥接仍可能用缓存配置继续请求旧云。现有语音管理及旧包激活在服务选择变化时递增版本；火山与 voxd 云端请求在共享锁内核对磁盘选择、版本和适用的密钥或服务地址，再发起请求。切换或切回后旧桥接拒绝调用并提示重启，已开始的请求仍可能完成。锁仍不覆盖其他通用配置写入，语音配置不应并发修改。

火山失败按白名单错误码写入固定脱敏日志，不写原始错误、密钥或合成文字。QQ 控制台火山自检分别显示合成和发送前置开关；合成成功不代表目标授权、频率及网关已就绪。旧云包试听和 Host 自检也在请求前核对选择版本；桌宠尚不支持火山直连，选择火山时返回结构化失败并保留文字，不再误调旧云。桌宠 API 和事件的失败信息已离线验证，真实桌宠界面是否展示仍未验。离线反例覆盖旧云→火山→旧云、旧云后备及试听被阻断、自检竞态、日志不含密钥、发送总闸及工具分别关闭；无真实云或 QQ 调用。

## 费用与失败路径

[官方V3 HTTP文档](https://docs.volcengine.com/docs/DoubaoVoice/HTTPChunkedSSEUnidirectionalStreaming-V3)使用相同 `/api/v3/tts/unidirectional`，说明 `20000000` 是合成结束成功帧，并提示流式WAV可能重复头部。当前实现必须收到该结束帧，仅合并每段RIFF/data长度完整、24kHz且 `fmt` 完全一致的整数PCM WAV（16字节fmt、无附加块、样本对齐）；多段合并时拒绝未知长度、附加块、压缩或格式不一致；单个完整WAV段允许结构完整的附加块。离线夹具覆盖分段、结束帧缺失与损坏反例；本机ffprobe确认合并样本是24kHz单声道16位PCM。没有真实火山响应证据，不能将这些条件当成官方所有实际响应的保证。
