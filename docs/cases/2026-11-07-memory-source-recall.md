## 完整逻辑

1. 链路：Host汇总/感知经历→统一记忆记录→src/memory-card.js的recordLine/renderMemoryCard→core上下文与B站生产构造器→模型。原记录含事件发生时间和视频来源，渲染层丢失精度与绑定。
2. 机制：同日多个视频仅显示年月日不足以判定最近，重要度排序也不是时间排序；评分理由不一定自带BV，不能要求模型凭相邻位置补关联。
3. 范围：仅清晰/鲜明、非私密、sourceChannel=bili且来源符合BV或BV:cid形式的视频经历，先由既有visibleFor受众规则决定可见性。实际ASR记录是restricted且仅allowedContexts=bili，不能误当private；本修法补其已获准上下文中的来源，不扩大受众。QQ、其它渠道、旧非视频来源、模糊/痕迹记忆保留旧形式；不写用户记忆，不新增模型或外发。
4. 取舍：扩大prompt、只改验收问法成本低却继续丢来源；在渲染拥有方保留已存结构化来源/ISO发生时刻，避免每个调用方拼第二套上下文，采用后者。BV仅从受限格式提取，不显示任意sourceId。
5. 生效：Host/桥接重启后新构造的上下文生效；已有磁盘prompt块需现有维护流程重建，不能只安装包便声称旧块更新。
