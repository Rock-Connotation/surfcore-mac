# B站记忆回忆丢失来源与同日先后顺序

## 现象与分析

Hy3低思考实际HTTP200、约33秒完成，取到了最近评分理由，却返回更早的BV。当前1775字上下文同时含同一天的两次转写，渲染只带日期；评分理由没有可见BV来源。持久记录的sourceId与createdAt均正确，不修写入账本来迎合答案。

假设依次为：渲染丢来源/精度；入库错绑视频；模型在完整信息下选错。原始记录已排除第二项，离线拥有方渲染测试用于锁住第一项；修复后仍须模型复验，不能由源码直接宣称模型召回通过。

## 完整逻辑

1. 链路：Host汇总/感知经历→统一记忆记录→src/memory-card.js的recordLine/renderMemoryCard→core上下文与B站生产构造器→模型。原记录含事件发生时间和视频来源，渲染层丢失精度与绑定。
2. 机制：同日多个视频仅显示年月日不足以判定最近，重要度排序也不是时间排序；评分理由不一定自带BV，不能要求模型凭相邻位置补关联。
3. 范围：仅清晰/鲜明、非私密、sourceChannel=bili且来源符合BV或BV:cid形式的视频经历，先由既有visibleFor受众规则决定可见性。实际ASR记录是restricted且仅allowedContexts=bili，不能误当private；本修法补其已获准上下文中的来源，不扩大受众。QQ、其它渠道、旧非视频来源、模糊/痕迹记忆保留旧形式；不写用户记忆，不新增模型或外发。
4. 取舍：扩大prompt、只改验收问法成本低却继续丢来源；在渲染拥有方保留已存结构化来源/ISO发生时刻，避免每个调用方拼第二套上下文，采用后者。BV仅从受限格式提取，不显示任意sourceId。
5. 生效：Host/桥接重启后新构造的上下文生效；已有磁盘prompt块需现有维护流程重建，不能只安装包便声称旧块更新。
6. 验证：官方Node24 `node --test scripts/test-memory-card.mjs` 29项通过。当前用例对Git对象eca92c1的原模块（只改私有副本的import定位）重跑，来源/时间断言明确红灯，修复绿灯；覆盖同日两视频/独立评分、原对象不变、QQ范围、模糊/痕迹、私密与非法来源。首轮私密夹具同时显式允许bili却期待被隐藏，预期错误；已改为受限上下文，并以完整卡确认正文可见而新增元数据不扩散，未修改既有权限语义。原始日志在私有20261107-followup。最终组合门禁与真实模型结果收工补记。
7. 回滚：回装原同源制品并保留新增数据；本改动不改记录/schema，不覆盖原账本。真实新模型回忆与其它设备仍需实证。
