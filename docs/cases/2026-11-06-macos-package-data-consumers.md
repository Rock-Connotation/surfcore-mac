## 现象与根因

包安装的程序目录在更新时可能被替换；QQ 数据已由共享解析器迁至 `DSH_HOME/surfcore/qq`，但账单、语音包、联网搜索配置和 DSH 端口缓存仍各自从程序根或 cwd 推导数据路径。包升级后可能看不到已有数据，或者把新状态写到下次更新会覆盖的位置。桌宠 `pet.js` 的 `root` 是 `stateDir/pet`，本就属于持久状态目录，无需修改。

## 完整逻辑

1. **链路**：账单生成读取 QQ token 和 bridge 遥测账本；语音管理器读取和保存安装状态、读取用量及配置、切换路由；联网搜索读取 QQ 配置；macOS DSH 发现把缓存作为候选排序提示并仍探测所属进程。它们共用 `resolveQqDataPaths` 的配置与状态路径；程序资源及语音包默认安装源仍按原代码根解析。
2. **机制**：有效 package 身份默认选择 `DSH_HOME/surfcore/qq`，明确指定的有效旧数据根继续使用旧目录；source 安装保留原路径和 cwd 语义。包目录检测到旧配置、状态或角色数据时直接抛有 code/hint 的错误，不复制或覆盖数据。端口缓存只影响排序，多个活跃 DSH 仍返回空结果。
3. **爆炸半径**：宿主账单、bridge 语音管理、搜索工具与 DSH 自动发现均可读取该状态；不修改模型、凭据或个人数据，也不执行外部发送。夹具均为临时假数据，未连接真实服务。
4. **取舍**：A 为每个消费者分别添加包判断，改动少但会出现多份互相漂移的路径规则；B 复用共享解析器，成本是给测试注入程序根并协调安装身份契约，获得统一冲突检测和可回滚的单一数据根。采用 B；原程序资源路径未迁移。
5. **生效与重启**：合并后需重新构建并重新加载插件和桥接进程；本会话未重启真实宿主。
6. **验证**：`node --test scripts/test-package-data-consumers.mjs` 4/4，真实调用账单生成、搜索配置读取、语音用量/状态/路由写入，以及以注入探测器验证端口顺序和多活拒绝；包含包、源码、包+显式旧根和遗留冲突。账单两项、语音默认值、搜索凭据边界、桌宠 API 和目录保护测试通过。网络和本机 App 未调用；原 `test-dsh-port.mjs` 使用真实回环服务，依本工单禁止网络未运行，由组合会话负责。
