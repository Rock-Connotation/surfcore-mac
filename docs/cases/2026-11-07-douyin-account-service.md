# 抖音账号与首页推荐服务（2026-11-07）

## 完整逻辑

- 链路：宿主传当前角色 id/epoch，服务仅使用该角色 `characters/<id>/douyin/` 下的开关、绑定和持久浏览器 profile。浏览器从固定 self 与首页推荐响应交给纯数据投影；上层只拿脱敏账号与最多五条推荐元数据。接口消费者在集成后仍须由宿主核对。
- 机制：人工在有头浏览器登录，只有新的 self 响应产生候选，确认候选才写账号。读取推荐先校验绑定身份，按请求发起序号切断旧响应，刷新取得首页推荐及 self，再刷新取得另一次 self；任一步缺失或账号变化均失败。cookie 不导出，不把文章作者或 cookie 当自身身份。self 格式尚待真实环境核验，无法识别则要求重新登录。
- 影响面：本地角色目录和自有浏览器进程；无模型调用、主动互动、发送、定时任务或资金操作。状态文件替换前备份，浏览器关闭不删除 profile，不等于退出登录。
- 取舍：直接抓取页面或复用全局浏览器成本较低，但无法可靠隔离账号与旧请求；独立 profile 和请求序号成本较高，换取可验证的角色与时间边界，回滚只需撤销服务代码并保留资料。
- 生效：集成宿主后需重启宿主；服务本身未接入 UI。停止只关闭本服务打开的浏览器。
- 验证：`node plugins/surfcore/scripts/test-douyin-service.mjs` 使用纯假浏览器和临时目录，覆盖候选确认、前后账号变化、旧请求、错误响应、角色切换、禁用、关闭失败与权限/备份。仓库 audit、regressions 和插件测试另行执行；未触及真实浏览器、账号或用户数据。
- 回滚与残余：撤销对应代码提交，不删除角色目录和备份。真实 self 响应与首页行为、验证码和真实 UI 未验证；看到推荐描述不代表观看或点赞，数量限制只约束返回数据，非网络请求数。

## 发布交接

功能：角色隔离的抖音人工登录绑定与有界首页推荐读取。验证：假浏览器测试及仓库门禁（以执行报告为准）。风险：真实平台响应与 UI 尚未验收；失败必须提示用户。发布前需合并宿主/UI，重新跑组合门禁并取得用户明确发布授权。无版本变更。

## 身份时序补修

独立审查复现候选倒序覆盖、已登出候选不失效和推荐读取 A→B→A 误成功。登录按 self 请求发起序号维护高水位，最新不可信或失败的 self 清除候选；确认前重新核对页面和候选。推荐读取从首次自账号验证后的固定 cutoff 起锁存任何已观察到的身份不符或未认证，不能被后续相同身份恢复；固定 cutoff 之前迟到的旧请求不参与判断，后续刷新不能上移身份监视门槛。离开 `https://www.douyin.com/` 时返回可行动错误且清候选，不返回页面内容。假浏览器测试钉住这些边界；真实页面与完整集成仍需另验。

## 角色切换准入补修

角色切换或恢复在关闭旧浏览器后仍可能等待其他渠道，期间旧角色 epoch 尚未变化。单独 invalidate 无法阻止此窗口重新打开旧角色浏览器，继而阻塞新角色。`withTransition(action)` 在首个等待之前关闭服务准入，取消旧操作后覆盖完整宿主 action；失败抛出含 code/error/hint 的关闭错误，并在 finally 释放计数。嵌套及并发操作计数归零前均不放行；期间状态读取可用，登录、确认、开关及推荐读取返回可操作的 `DOUYIN_TRANSITION`。宿主必须用该接口包裹完整切换和恢复，单独本服务不代表宿主已接线。
