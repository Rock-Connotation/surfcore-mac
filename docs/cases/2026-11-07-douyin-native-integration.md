# 抖音账号、推荐读取与官方 App 接线

## 现象与范围

用户要求盘点 QQ/B站之外的渠道，先经 Context 查询 GitHub 开源库，再优先实现抖音账号登录与推荐流。此前抖音只有类型枚举，没有登录、适配器或设置页。实现为默认关闭、当前角色独立账号、人工扫码、主动读取最多五条推荐文案；不自动发布、互动、调用模型或写观看经历。

## 完整逻辑

1. **链路**：官方 DSH Desktop Host 加载 `plugins/surfcore/lib/index.js`，注册抖音 runtime 与既有鉴权前缀下的 `/dsh-surfcore/api/douyin`；`client.js` 的抖音页调用 `douyin-api.mjs` → `douyin-service.mjs` → `douyin-browser.mjs` → 本机 Chrome/Edge 专用 profile。`douyin-data.mjs` 只投影身份及公开推荐字段；同一角色的开关、绑定、浏览器资料分别位于 `STATE_DIR/characters/<id>/douyin/`。普通 QQ/B站链路仍使用各自原有入口。
2. **机制**：类型名称、游客推荐、作者作品都不能证明当前账号推荐。实际页面需固定 `https://www.douyin.com/?recommend=1&from_nav=1`，缺少 `from_nav=1` 曾落入精选。只接收当前自有浏览器发起的 HTTPS 官方 self/feed 精确路径；关闭 HTTP cache，阻止 Service Worker，按请求启动序号与当前浏览器世代区分迟到响应。首次账号候选必须确认；读取前、读取中和读取后核对绑定身份，账号变化或失效一旦发生则本轮失败，不允许后来的相同账号将其复活。角色切换/回档的整个异步过程通过 `withTransition` 阻止新操作。
3. **影响面**：一个 Desktop Host、一个按需自有浏览器及一个设置页消费者；角色资料属于用户数据，失败必须可见而非静默。源接口正文仅在进程内解析，公开结果不含完整账号 UID、Cookie、手机号、签名查询或媒体地址。浏览器使用允许列表环境变量，不继承 provider 凭据。无模型费用和 QQ 外发；仅正常页面导航/有界翻页会影响该专用账号的浏览推荐记录。推荐文案是外部资料，不等于完整观看、赞同、ASR 或点评。
4. **取舍**：A，用 F2/API 服务维护签名和 Cookie，可直接得到结构化数据，但新增 Python/原生依赖或 PostgreSQL/Redis 等服务，扫码及个人推荐语义仍未证明；B，用用户扫码的独立浏览器监听自然网络响应，账号与页面可以核对，但需管理进程和页面变化。选择 B。最初手写 CDP 能核身份但推荐捕获不稳定，继续补协议成本偏高，改用 Apache-2.0 `playwright-core@1.65.0`（不下载浏览器），保留纯数据层和身份状态机。开源研究及固定源码见 [选型案例](2026-11-07-douyin-source-selection.md)。
5. **生效与重启**：代码和依赖由 Host 加载，安装候选后需完全退出并重开该独立官方 App；角色内开关立即生效。Chrome 原生资料独立保存；macOS 保留原生 keychain，使用会话恢复参数。`context close` 不是 OS 进程退出证据；只复用首次主动 close Promise，正常完成并经 SDK 进程清理后才释放锁。意外断连或关闭超时保留引用和锁、拒绝重新启动，提示管理员核对原进程；不全局杀浏览器或自动删除未知锁。
6. **验证**：专项覆盖真实调用契约的模拟响应、来源拒绝、身份时序、角色世代、转场并发/嵌套、关闭超时/断连、API Origin/JSON/旧角色结果、前端错误持续可见。运行 `npm run test:audit`、`npm run test:regressions` 与完整插件测试；发布清单从 git 对象生成。模拟通过只证明代码边界，真实账号持久化、推荐与原生 UI 需要单独取证，见下方当前记录。
7. **回滚与残余**：关闭当前角色抖音并确认自有窗口已退出；旧制品可重装，保留新角色资料和备份。不会删除浏览器 profile、账号绑定或已有 QQ/B站数据。平台风控、接口变化、Windows 真机、睡眠恢复、长期稳定性未由本轮单次验收证明；视频下载/ASR/自主点评/定时刷推荐/互动不在本期通过范围。

## 当前验证记录（实施中）

- Context7 与固定 GitHub 源码研究完成；没有引入 F2、Download API 服务或 GPL 插件代码。
- 用户在专用 Chrome 手工扫码，官方 self 接口曾返回有效身份；只记录昵称和 UID 尾号。切换到 SDK 后登录在重启时失效，先前的“资料存在”不足以证明登录持久化。
- Playwright 实际捕获 `/aweme/v1/web/tab/feed/` 的 HTTP 200、`status_code=0`、有效推荐条目；当时页面未登录，**只算游客推荐捕获，不算该账号推荐通过**。
- 已增加会话恢复与原生 keychain 兼容，等待用户在同一专用窗口重新登录后验证关闭/重开与绑定身份。
- 独立强审查出的整段角色转场门闸、断连不提前释放锁已修复；组合门禁、同源安装及官方原生 App 验收待完成。
- 私有证据位于 `_backups/20261107-douyin/`，不随包分发；不得复制账号凭据、完整 UID 或原始页面到公开报告。
