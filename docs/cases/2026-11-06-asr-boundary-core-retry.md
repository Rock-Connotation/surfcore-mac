# ASR 分块边界时间戳失败与有界重试

## 现象、链路与机制

隔离官方 App 的 241 秒公共拼接录音在中断后恢复，首块 WAV 长 241000 ms，whisper.cpp 最后一段输出 238000–242000 ms，超过素材末尾 1000 ms。严格解析器以 `OUTPUT_INVALID` 拒绝该块；第二块执行成功，作业正确显示 partial，缺失 0–240000 ms。第二块的跨界句也被原先的中心点规则丢弃。证据见本次隔离验收的 `native-recovery-result.json` 和对应作业原始 JSON；不将该素材当作真实业务视频或质量验收。

上游渠道提交媒体后，Host 共享队列经 FFmpeg 生成 PCM、分块，whisper.cpp 返回 JSON，`src/perception/whisper.js` 进行严格时间轴校验，`service.js` 映射来源、写检查点及覆盖结果。首块超界触发一次仅针对核心区间的同队列重试；原输出和核心重试输出分别保留。只有结构化 `segment-out-of-bounds` 触发，损坏 JSON、空文本、进程失败和取消均不触发。核心重试也无效时仍 partial，不再递归尝试。实际 provider 试验中 240 秒核心输出合法，另一条 120 秒输入仍超界，说明不能承诺重试必然成功。

## 影响与取舍

影响共享 ASR 的各渠道，单槽串行不变；一次核心重试增加至多一次解码与推理，磁盘估算也预留额外分块。方案一直接放宽或裁剪越界输出，成本低但无法证明边界文字与时间可靠；方案二保持严格解析并仅重试核心区间，成本是一次额外本地推理，失败仍可诊断和恢复，故选方案二。重试成功警告说明边界文字可能不完整；处理覆盖仅代表请求音频范围已处理，不证明识别准确或句子未遗漏。没有更改模型、用户数据或云路由。

有效语句只要与核心区间有正交集即保留完整合法时间戳；跨相邻块、共享对应边界、文本一致且时间高度重合时去重。边界不确定时宁可保留重复。中间块携带两侧边界；查找不只比较上一句。检查点的警告与摘要共同保存、恢复时重验并重现警告。缓存键加入处理算法版本，旧结果和检查点不复用；旧 job schema、历史和关联记录保留，旧 queued 作业启动时重新计算键，确保取消找到正确 runner。

## 生效、验证与回滚

Host 载入新源码后生效；真实运行中的 DSH 需由主会话在授权的隔离安装流程中重载。本地测试 `node scripts/test-perception-service.mjs` 使用独立根与 fake provider，验证精确两次推理、两次均失败仍 partial、其他错误不重试、跨界句、三块边界去重、核心时间偏移、警告恢复、旧缓存/检查点隔离和取消/关闭回收；配套执行 `node scripts/test-perception-resources.mjs` 与 Host CLI 夹具。真实 App 回归需另由主会话执行；不把 fixture 证明等同实际 App 或质量达标。

回滚源码时恢复旧服务、解析器和缓存键实现；保留 job、原始输出、检查点与用户素材。新版本生成的缓存不可由旧算法安全复用，回滚时应保留并隔离版本化缓存，不能删除用户数据。错误和处理范围仍需在 UI 展示。

## 发布交接块

- 范围：ASR 边界时间戳一次有界核心重试、跨界文字映射和保守去重；无配置迁移。
- 影响：失败边界最多增加一次本地推理，成功时可见 `ASR_CORE_RETRY` 提示；重试失败维持 partial。
- 验证：隔离 fixture 与资源、CLI 回归；真实官方 App 长音频重验由主会话完成。
- 回滚：恢复相关源码，隔离新算法缓存并保留历史作业；不删除素材。
- 版本与发布：本次不 bump、不发布。

队列启动迁移补充：读取旧 queued 作业时只在内存重算新缓存键，由入队步骤统一持久化；注入写盘 ENOSPC 时初始化明确失败、doctor 返回 code/error/hint，原作业文件保持 queued，不会在 Host 显示就绪的同时静默消失。
