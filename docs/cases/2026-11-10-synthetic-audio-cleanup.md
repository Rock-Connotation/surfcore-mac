# 清理累积的合成 ASR 测试音频

## 现象与根因

重复运行 `scripts/test-perception-service.mjs` 会把 `ffmpeg lavfi sine` 生成的 481 秒音频及多个正规化副本留在 `_backups/asr-test-<timestamp>-<pid>/`。完整批次约 354 MiB，本次共发现 55 批；不是火山真实合成或用户录音。此前 Memory V2 审计因 `ASR_DISK_SPACE_LOW` 失败，不能把该拒绝当通过。

## 完整逻辑

1. **链路**：两棵工作树的同一 ASR 回归脚本产生测试 assets、jobs、cache。逐目录统计并用进程/打开文件记录检查占用；不扫描或清理常用 DSH 的配置与会话。
2. **机制**：合成测试输入与正规化副本每轮永久累积，几轮门禁即可新增 GiB。符号链接是专门的安全反例；归档保存链接本身，检查其目标仍在批次内部，不跟随链接。
3. **影响面**：仅 `surfcore-memory-v2/_backups/asr-test-*` 与 `surfcore-volc-voice/_backups/asr-test-*` 的 55 个已核验目录。无源码、真实凭据、预算、生产模型、回滚程序或真实验收包删除；无网络与付费操作。
4. **取舍**：直接删除最快但丢失失败现场；本次选择完整压缩、逐内容校验后再删原目录，保留约 656.90 MiB 可恢复证据，释放大部分空间。真实验收与回滚材料单独保留。
5. **生效**：删除已完成，无需重启。任何新测试产物或之后运行中的目录不属于冻结清单；本次不改变测试断言或磁盘门槛。
6. **验证**：10,852 个文件/链接归档项校验通过；删除前重查打开文件、路径、size/mtime 与目录集合；55 删除、0 跳过，删除后逐目录不存在。输入约 11.55 GiB；磁盘可用空间实测增加 11.10 GiB，最终约 11.85 GiB。并发进程可能影响可用空间统计，不把目录逻辑大小等同 APFS 实际释放量。
7. **回滚与残余**：从仓库外 `../_surfcore-test-artifacts-20261110/synthetic-asr-before-cleanup.tar.gz` 按 manifest 恢复；保留符号链接时需选择原根路径。旧审计失败的 job.json 也在该归档对应的原相对路径内。空间已恢复不代表最终审计已通过，仍需重跑。脚本目前仍会生成持久测试批次，后续验收后继续按相同规则清理，避免重新累积。
