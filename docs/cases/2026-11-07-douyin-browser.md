# 抖音独立浏览器传输（2026-11-07）

## 现象与环境

抖音账号登录与推荐流需要用户在官方页面操作，现有 B 站扫码传输使用临时资料和 WebSocket，不能直接提供可持续的抖音独立登录资料。macOS 开发环境，SurfCore 0.8.8；本次仅实现独立传输，尚未接入用户界面。

## 根因和完整逻辑

- **链路**：调用者创建 `douyin-browser.mjs` 实例，模块启动自己持有的 Chrome/Edge 子进程，通过 fd 3/4 上 NUL 分帧 CDP 控制官方首页；固定路径的 JSON 响应交给调用者。没有外部命令或任意 URL 接口。
- **机制**：Chromium 使用私有持久 profile 保留登录，独占锁阻止两个实例抢占；只在自有子进程退出后移除自身锁，不删除资料。异常残留锁不自动认领或删除。输出 URL 和网络诊断不含 query/header；响应正文只传递固定官方主机与路径的最多 2 MiB JSON，不打印正文。仅接受同一附着会话中已观察到请求起始、无重定向且起始与响应路径一致的请求；回调携带 requestId、sessionId、递增 requestSeq 和 requestStartedAt，供上层对登录代次和截止点过滤。
- **爆炸半径**：一个自有浏览器进程、一个调用方、失败有结构化错误；涉及登录资料但不读取或导出 Cookie，不涉及支付或自动外发。之前未有该模块，真实页面与协议兼容性尚未验证。
- **取舍**：复用现有 WebSocket 扫码模块成本小，但 TCP 调试端口和临时资料不符合需求；选择专属管道和持久目录，成本是明确维护进程、锁和协议生命周期，回滚仅移除新模块，资料需原样保留。
- **生效与重启**：模块当前没有接入调用方；整合后需重新加载宿主插件并启动独立浏览器，不影响其他浏览器 profile。

## 修法、验证与回滚

不设调试 TCP 端口，未使用用户现有浏览器 profile；启动传入绝对私有目录，限制目录权限与符号链接，记录占用锁；固定首页导航，固定脚本返回有界页面文本与截图。调用失败给出 code/error/hint。退出仅发送 Browser.close 并等待自有子进程，超时不强杀。

回滚为撤销本模块及调用接入；用户资料和未知锁先保留，人工检查后处理。自动化使用假子进程模拟管道：UTF-8 分片、固定导航、关闭、锁、资料保留、allowlist、超限、命令错误及超时；无真实账号、网络、浏览器、平台或外发操作。官方 Node 24：专项假浏览器通过；隔离 HOME 下审计 169/169、回归和插件全量测试退出码均为 0。审计与插件套件不包含未接线的新模块，专项测试覆盖本模块。

## 未验证与发布交接

真实 Chrome/Edge 的 fd 3/4 协议、登录交互、真实响应结构及推荐流由组合会话验收；不宣称登录或推荐流已通过。未连接 UI，因此用户可见失败展示由接入方负责。异常退出遗留锁须由人工检查，不自动恢复。

交接：文件 `plugins/surfcore/lib/douyin-browser.mjs`、`plugins/surfcore/scripts/test-douyin-browser.mjs`、本 case；新增内部接口，未修改既有接口；建议按完整功能组合后的发布决策定版本；失败分支通过模拟测试，真实平台未验；无版本变更或发布。
