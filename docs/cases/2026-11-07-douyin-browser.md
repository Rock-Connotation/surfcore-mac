# 抖音独立浏览器传输（2026-11-07）

## 现象与环境

抖音账号登录与推荐流需要用户在官方页面操作，现有 B 站扫码传输使用临时资料和 WebSocket，不能直接提供可持续的抖音独立登录资料。macOS 开发环境，SurfCore 0.8.8；本次仅实现独立传输，尚未接入用户界面。

## 根因和完整逻辑

- **链路**：调用者创建 `douyin-browser.mjs` 实例，模块启动自己持有的 Chrome/Edge 子进程，通过 fd 3/4 上 NUL 分帧 CDP 控制官方首页；固定路径的 JSON 响应交给调用者。没有外部命令或任意 URL 接口。
- **机制**：Chromium 使用私有持久 profile 保留登录，独占锁阻止两个实例抢占；只在自有子进程退出后移除自身锁，不删除资料。异常残留锁不自动认领或删除。输出 URL 和网络诊断不含 query/header；响应正文只传递固定官方主机与路径的最多 2 MiB JSON，不打印正文。仅接受同一附着会话中已观察到请求起始、无重定向且起始与响应路径一致的请求；回调携带 requestId、sessionId、递增 requestSeq 和 requestStartedAt，供上层对登录代次和截止点过滤。
- **爆炸半径**：一个自有浏览器进程、一个调用方、失败有结构化错误；涉及登录资料但不读取或导出 Cookie，不涉及支付或自动外发。之前未有该模块，真实页面与协议兼容性尚未验证。
- **取舍**：复用现有 WebSocket 扫码模块成本小，但 TCP 调试端口和临时资料不符合需求；选择专属管道和持久目录，成本是明确维护进程、锁和协议生命周期，回滚仅移除新模块，资料需原样保留。
- **生效与重启**：模块当前没有接入调用方；整合后需重新加载宿主插件并启动独立浏览器，不影响其他浏览器 profile。

## 修法、验证与回滚

不设调试 TCP 端口，未使用用户现有浏览器 profile；启动传入绝对私有目录，限制目录权限与符号链接，记录占用锁；固定首页导航，固定脚本返回有界页面文本与截图。调用失败给出 code/error/hint。退出仅发送 Browser.close 并等待自有子进程，超时不强杀。

回滚为撤销本模块及调用接入；用户资料和未知锁先保留，人工检查后处理。自动化使用假子进程模拟管道：UTF-8 分片、固定导航、关闭、锁、资料保留、allowlist、超限、命令错误及超时；无真实账号、网络、浏览器、平台或外发操作。官方 Node 24：专项假浏览器通过；隔离 HOME 下审计 169/169、回归和插件全量测试退出码均为 0。审计与插件套件不包含未接线的新模块，专项测试覆盖本模块。

## 未验证与发布交接

真实 Chrome/Edge 的 fd 3/4 协议、登录交互、真实响应结构及推荐流由组合会话验收；不宣称登录或推荐流已通过。未连接 UI，因此用户可见失败展示由接入方负责。异常退出遗留锁须由人工检查，不自动恢复。

交接：文件 `plugins/surfcore/lib/douyin-browser.mjs`、`plugins/surfcore/scripts/test-douyin-browser.mjs`、本 case；新增内部接口，未修改既有接口；建议按完整功能组合后的发布决策定版本；失败分支通过模拟测试，真实平台未验；无版本变更或发布。

## 审查补修：管道中断与旧缓存（2026-11-07）

- **现象与机制**：原先 fd 管道关闭、写入报错或帧超限只拒绝待处理命令，状态仍报告运行；缓存和 Service Worker 响应也可能被误认作本次身份下的新请求。上层即使按请求起始时间过滤，也无法据此证明正文不是旧缓存。
- **修法与所有权**：管道故障改为 `BROWSER_DISCONNECTED`（含 error/hint，`running:false`），阻止继续操作；只尝试给自有管道正常 EOF 并等待真实子进程退出，超时明确失败，锁与资料不释放、不强杀。正常退出才能解锁；下次启动需等原进程退出。请求响应明确标记来自磁盘、Service Worker、预取缓存或收到 `requestServedFromCache` 时不交出正文。
- **取舍与影响**：方案 A 仅透传缓存标志，由每个调用方判定，兼容更多内容但容易漏掉；方案 B 在固定自账号/推荐正文出口直接拒绝缓存，成本是可能少拿数据，能避免旧身份内容误入观测。选择 B。故障只影响一个自有浏览器和其调用方，不删除资料或调用网络；模块接入后重新加载宿主生效。回滚到修复前提交会恢复错误在线状态和缓存误判，不建议回退。
- **验证**：假子进程覆盖读端关闭、写端断开及超限，核对失败状态、失败提示、重复启动拒绝、关闭未证实退出不报成功、退出前锁保留及实际退出后释放；四类缓存均不交正文。原代码在新增缓存断言下实际收到 5 条而预期 1 条；三种断管/超限模拟各自均在状态断言失败，修复后专项通过；Node 24 回归及插件全量退出 0。复跑审计 168/169：`test-release-manifest.mjs` 的 HEAD 清单缺本次三个新增文件，组合会话需更新清单后重跑；先前 169/169 是添加这些文件到 HEAD 前的基线。真实浏览器、真实账号及平台未运行，仍由组合会话验收。

## 路线替换：Playwright 持久上下文（2026-11-07）

- **链路和机制**：服务通过同一工厂启动私有持久 profile 的 Chrome/Edge；`playwright-core` 自有管道管理上下文，并在上下文级监听所有页面、子帧与工作线程请求。首页固定 `https://www.douyin.com/?recommend=1&from_nav=1`。仅 `www.douyin.com` 的 self 与 tab/feed 读取 JSON；其它路径只产出无 query 的元数据，不视作个人推荐。请求开始即时生成独立序号、时间和上下文 ID，响应必须对应同一请求且无重定向。正文不打印、不导出 Cookie；编码体大小及解码后大小各限 8 MiB。`context.route` 启用路由会禁用 HTTP 缓存；同时 `serviceWorkers: 'block'`，并再次拒绝标记来自 Service Worker 的响应。它不依赖虚构的 Playwright 缓存标志。
- **现象与取舍**：手写 CDP 只附着单一页面，推荐网络事件易漏；继续维护多目标附着需长期维护协议及重连。改用 Playwright 的持久上下文成本是新增运行依赖，收益是 SDK 维护跨目标事件和自身进程生命周期；回滚为还原此次代码并保留 profile，不能删除登录资料。上下文启动只传系统所需环境变量，使用本机已有浏览器，不下载浏览器或接入现有浏览器。
- **影响与失败**：仅独立浏览器与调用者，涉及用户登录资料，无自动点赞、发送、支付或破解验证。验证页返回 code/error/hint，用户自行处理；关闭未确认时保留引用与锁，迟到响应不交付。教程仅识别指定文案及精确按钮，显式加载时最多发送四次向下键，不把按键等同推荐已更新。重启宿主插件并启动独立浏览器后生效。
- **验证与限制**：假 SDK 专项覆盖私有目录、外来 profile 拒绝、重复锁、请求关联与脱敏、重定向、Service Worker、超限、旧响应、关闭超时和再次启动，以及导航、人工验证和键盘边界；没有真实浏览器或网络。HTTP 缓存禁用依赖 Playwright 路由语义，实际页面、磁盘缓存与进程退出仍须由组合会话实机验证。正文长度在 SDK 返回后再检查解码字节，不能作为流式内存上限。

发布交接：内部传输换成 Playwright 持久上下文，个人推荐和账号捕获路径不扩张；保留资料、人工验证和退出失败可见。依赖及许可证由组合会话整理；专项假 SDK 已通过，完整门禁和真实 Chrome 登录、个人推荐须以组合会话最终结果为准。无版本变更、发布或推送；回滚程序时保留独立 profile 和未知锁。

本树官方 Node 24、隔离 HOME 检查：抖音 browser/data/service 三项和 `npm run test:regressions` 通过；`npm run test:audit` 为 167/169。失败是 HEAD 清单缺 9 个已有抖音文件，以及共用依赖按 `--ignore-scripts` 安装后 `@snowluma/sdk` 未执行兼容补丁、Node ESM 无法解析；两项均留给组合会话处理，不能称完整审计通过。首次未接依赖的审计 128/169，存在缺 `js-yaml` 和宿主 DSH 工具差异，不能作为最终门禁。审计记录 `/tmp/surfcore-douyin-playwright-audit.log`。

组合会话实机观察到固定 feed 路径能返回 JSON，但原生 profile 既有登录未恢复；移除 Playwright macOS 的 basic/mock-keychain 默认参数也未证明能恢复已经失效的登录。为兼容专用 profile 的系统钥匙串，macOS 启动忽略这两个默认参数；`--restore-last-session` 尝试保留会话 Cookie，启动后只保留一个自有页面，再由新导航重新建立观测。假 SDK 已断言启动参数与多余页面关闭；账号在实际重启后是否保持登录仍需主线复验，不能把该选项当持久化证明。参考 [Playwright issue 36139](https://github.com/microsoft/playwright/issues/36139)。加载方法报告实际发送的 `keyStepsSent`，不声称页面已切换。

## 审查补修：连接中断不等于进程退出（2026-11-07）

- **链路与根因**：Playwright 上下文 `close` 事件既可能来自正常关闭，也可能来自控制通道断开；此前事件监听直接删除自有锁，可能在进程仍活着时允许第二个实例占用同一 profile。正常主动关闭的原始 Promise 则沿 SDK 的浏览器关闭及子进程清理链等待完成。
- **影响与取舍**：只影响独立 profile 的所有权；误释放可能并发损坏登录资料。方案一以事件释放锁简短，但无法区分断连；方案二保存主动关闭发起的单个 Promise，只有其成功才释放。选方案二；非主动断连、失败和超时均保留引用与锁，明确提示管理员确认进程退出后处理。超时后的再次关闭只等待同一 Promise，避免已断连的 SDK `close()` 空返回被误作退出证明；迟到成功可释放锁。资料不删除。
- **验证与生效**：假 SDK 断言意外 close 事件、关闭期间事件先于 Promise、拒绝与超时都不解锁；迟到原始 Promise 成功与普通主动关闭才解锁，重启同一对象可用。无真实浏览器、账号、网络或进程操作。插件重载生效；回退此补修会恢复误解锁风险，不建议回退。独立审核的 SDK 调用链证据由组合会话保留。

发布交接：修复独立浏览器断连误释放资料锁；失败返回结构化状态与处理提示，保留原资料。假 SDK 专项和隔离回归需通过；不改版本、不发布，真实退出行为由组合会话实机验证。
