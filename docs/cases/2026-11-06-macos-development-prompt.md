# 本地 Agent 开发提示词

## 现象与根因

用户要求按功能提交已有文档，并提供可让本地 Agent 根据 macOS 技术设计直接开发的 prompt。
设计原稿在忽略目录，Git 工作树不会继承；旧通用交接模板又使用历史 Windows 环境和旧待办，不能直接作为这次 macOS 开发入口。

## 完整逻辑

1. **链路**：`docs/README.md` / HANDOFF → [MACOS-DEVELOPMENT-PROMPT.md](../guides/MACOS-DEVELOPMENT-PROMPT.md) → 本地设计 01—07 → 新开发工作树 → WP0—WP5。提示词独立可复制，不需要复述本会话。
2. **机制**：把目标、输入携带、基线复核、实施依赖、验收和授权写清；源提交固定设计出处，开发起点保留最新交接。实际 API、文件名和依赖能力仍从当前源码核对。
3. **影响面**：只新增开发交接文字与索引，运行进程改动数 0；本会话没有启动功能实现、变更用户数据、付费调用或真实外发。
4. **取舍**：短句“按设计开发”省阅读成本但遗漏资料复制、已有红灯和验收标准；把全部设计复制进 prompt 又易漂移。本次选任务入口加 WP 依赖与关键完成标准，细节回到原分册。
5. **生效**：用户把 prompt 发给本地 Agent 后才开始执行；无需为文档重启 DSH。真实账号/数据操作、共享运行时和发布保留其既有授权边界。
6. **验证**：逐项对照 05 的依赖与 06 的编号验收，核验文档相对链接及 staged diff；运行时代码、锁文件、测试脚本与前两批相同，复用此前门禁证据，不重跑同一套运行时测试。audit 尚余 6 项未解决、插件更新器基线失败，详见 [原案例](2026-11-06-development-tools-and-macos-design.md)，不宣告全绿。
7. **回滚与残余**：本批编辑前文件在 `_backups/20261106-functional-commits/before-prompt/`；回滚前保存后来修改，新增文档可隔离移出。提示词未交给另一 Agent 实际跑完，macOS 首期开发与实机验证仍未开始。
