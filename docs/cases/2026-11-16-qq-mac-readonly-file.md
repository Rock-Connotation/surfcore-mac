# 2026-11-16 QQ 主人私聊读取 Mac 文本文件

目录清单真机通过后，接入 `任务：读取文件 alpha-notes.txt`。这次批准的正文读取目录为上次验收的 `qq-readonly-nAJcwO`。

## 完整逻辑

1. **链路**。OneBot 入站 → QQ 桥接确认主人、私聊白名单、登录账号及角色 → Task Harness → 只读文件描述符 → 原私聊文字回执。`任务：读取文件` 在普通聊天、Memory V2 与模型提交路径之前处理。
2. **机制**。本地 QQ 状态的 `task-files.text-directory` 写入一个获准子目录名，文件属本机用户且权限为 `0600`。只读该目录当前层、本人拥有的普通 `.txt`，拒绝符号链接、硬链接、子路径、非 UTF-8 和超过 2400 字节的正文。读前后比较文件身份和时间戳，发送排队时重新核对授权文件、目录身份与私聊上下文。正文保持原文，检测到已知凭据模式或 QQ 控制码时报错。
3. **影响面**。新增 QQ 主人私聊命令。账本只留字节数及回执，正文只进入 QQ 私聊回执，不进模型、记忆或任务账本。文件以只读模式打开。抖音与 B 站不参与本次验收。
4. **取舍**。扩展已有网页研究或终端入口，需要给执行器更宽的权限。复用固定只读任务与管理回执，运行开销小，只需一个可撤销的本机目录授权。
5. **生效**。本机写入目录授权后，只重启 QQ 桥接以加载实现。NapCat 登录、DSH 宿主及其他渠道无需重启。移走授权文件即撤销后续读取，排队中的正文也会在送出前被拦下。
6. **验证**。`node scripts/test-owner-delivery-r3.mjs` 覆盖字节还原、并发去重、越界、链接、撤权、非主人和群聊。真机从 QQ 发上述命令，通过 OneBot 查原入站和私聊回执，并核对回传正文与 Mac 文件字节一致。
7. **回滚**。将 `task-files.text-directory` 移入本机备份即可撤销正文权限。完整回滚则还原备份中的 QQ 程序文件和制品元数据，再启桥接。保留原目录、任务账本和 QQ 历史。
