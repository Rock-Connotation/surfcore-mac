# 严格隐私扫描发现历史本机路径与报告标识

## 现象、机制与取舍

严格扫描首轮失败46项，均为继承内容：45项路径命中，同一报告行另有1项高熵标识。逐项清理后又显露被每文件每规则最多三条报告上限遮住的旧路径；继续逐项处理至零。另把历史凭据排查示例中的检索片段移出公开文档。不能把扫描零命中解释为全历史无秘密。

候选一是放宽扫描规则/把文档放入白名单，成本低但不能消除公开材料中的本机信息，长期风险高；候选二是仅替换静态材料为含义明确的占位符，保留根目录与父目录、中文/空格路径等故障机制说明。采用第二条，备份和Git可回滚，无运行配置迁移成本。

## 完整逻辑

1. 链路：Git跟踪的README/历史交接/case/指南与四处源码静态提示或注释→严格隐私扫描→发布候选；UI提示还被原生设置页/桌宠失败面板读取。没有改运行时路径候选、认证、账号、配置或用户数据。
2. 机制：历史故障说明直接粘贴本机绝对路径，报告文件名又含不宜公开的标识。改为有意义占位符；用户实际需操作的浏览按钮、完整带盘符路径和根目录关系仍保留。
3. 范围：22个已有文件的静态内容与本case；代码仅client.js、pet.js、snowluma-install.js、snowluma-conn.js的字符串/注释。不修改扫描器、规则、allowlist或Git历史；旧历史仍可查到原内容，不称泄露事件已消除。
4. 取舍：以上两路线对比；采用源头清理，不增加新依赖。原文在本地隔离工作树的私有备份，公开文档只保留必要故障语义。
5. 生效：文档立刻生效；提示语需安装新包并重启Host/刷新设置页。桌宠缺盘符失败仍保留pet.path-no-drive与非空hint，引导填写完整路径或点浏览。
6. 验证：`node scripts/privacy-scan.mjs --strict --json` 最终ok=true、findings=[]、incomplete=[]；`git diff --check`通过。组合候选还须audit和插件检查，最终结果在主线交接补记；不因静态扫描通过宣称真实UI验收已完成。
7. 回滚：从Git对象回退这组静态内容或重装旧包，保留用户数据；原始文本私有备份保留。回退会恢复扫描命中；历史清理与凭据轮换不属于这次静态材料修复。
