## 完整逻辑

1. **链路**。QQ 经 NapCat 的 HTTP 与 WS 到桥接。B站二维码写持久分字段凭据；Host V2 transport 经官方 nav 与收件/发送接口，用同一凭据快照。DSH 的发现日记与本机分享有独立控制器和授权。抖音推荐读到配额内候选后，companion 对每条素材捕获独立 Memory V2 句柄。
2. **机制**。QQ 的 OneBot 在原账号登录后才启动。B站此前直接将分字段 JSON 交给只接受 Cookie 字符串的 V2 transport，「仅受控单轮」又让旧监听整体不启动。抖音此前读完推荐便关闭 Chromium，随后每次素材捕获又重新启动官方身份探测。日记的拒绝状态原来不给当前角色，iframe 因而从未发起独立聊天查询。
3. **影响面**。QQ 只恢复原容器与原账号。B站接线影响宿主对官方账号、来源与发送的使用；Cookie 不输出、不写回。显式受控评论监听仅注册评论收件，不注册巡航、动态提醒、直播、私信，默认关闭。DSH 伙伴页只回显当前角色 id、epoch、name 与结构化错误；发现内容和本机回复分别受原授权约束。
4. **取舍**。B站选择兼容原凭据文件并重读比较快照，避开转换落盘或重新扫码。受控评论复用现有监听与退役链路，避开取消受控模式后让其它定时任务也运行。抖音选择一轮持有已核对的浏览器，保留每条素材独立授权与来源；来源仍从同一 profile/账号/角色世代核对，超过 30 秒在该浏览器重验，退出、角色切换或已观测的账号漂移会阻断。单纯把反复重开的浏览器改成无界面模式，在本机真实登录态验证失败。
5. **生效**。NapCat 原容器重启后由用户扫码。B站与 DSH 页面修复由 SurfCore Host 加载；替换程序后重载宿主或重启 DSH，再读回 QQ 桥接健康。受控评论入口在 B站监听配置。
6. **验证**。B站 transport 新增真实扫码形状回归，修前 BILI_OFFICIAL_CREDENTIALS_UNAVAILABLE；修后官方 nav 只读实测确认账号。scheduler 夹具验证只开放评论路径、其它四类显式调用被拒。真实浏览器与真实分享控制器的组合夹具验证日记拒绝可见但本机分享可发送。抖音服务夹具断言一轮两次核验同浏览器，并在账号漂移后拒绝、取消后关闭。
7. **回滚与残余**。恢复旧插件程序后重载宿主。用户账号、授权、QQ 收件、角色、观看记录和额度属于运行数据，回滚程序不恢复它们。B站需新通知与送达证据。本机合并许可仅用于此次实测，测试记录仍受撤回后的原始来源权限约束。页面独立身份核验仍会在观看轮次之外启动浏览器。

最终门禁：`npm run test:audit` 207/207，协议回归及完整插件套件通过；权限恢复补修的真实 Worker、管理控制器和桌面 UI 夹具通过。
