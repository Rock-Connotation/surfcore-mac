# 抖音自账号与首页推荐数据投影（2026-11-07）

## 现象与范围

账号接入需要区分当前登录用户与任意作者，并只把首页推荐所需的公开元数据交给下游；直接透传上游响应可能泄露账号标识、媒体地址和私人资料。本改动仅提供纯函数，尚未接入网络、界面或登录流程。

## 完整逻辑

- **链路**：调用方将可信且新鲜的固定 self endpoint 响应交给 `parseDouyinSelf`，将固定首页推荐 endpoint 响应交给 `parseDouyinFeed`；`publicDouyinAccount` 为界面提供脱敏账号投影。目前没有生产调用者。自账号结果的 UID、secUid、accountKey 仅供内部身份绑定。
- **机制**：状态和形状是必要条件而非来源证明。只认来源路径 `/aweme/v1/web/user/profile/self/` 与 `status_code: 0/user.uid/nickname`；passport 形状尚无足够证据，暂不接。调用方必须限定新鲜自账号 endpoint 并首次由真人确认身份。首页要求来源路径 `/aweme/v1/web/tab/feed/` 并按 `status_code: 0/aweme_list` 校验，每次最多五条，构造规范视频 URL；作者投稿和相关视频也可能使用同样的 JSON 形状，调用方必须从浏览器响应元数据提供来源路径，不能接受用户自填路径；不能仅凭本模块认定来源。F2 固定版本 `f6be8c0ffba9a127075bbeafe4838716650b6325` 的 `fetch_post_feed` 指向 `/aweme/v1/web/tab/feed/`；名为 `fetch_user_feed_videos` 的方法实际上是作者投稿，不能代替首页流。上述形状为受限假设，尚需真实响应验证。
- **爆炸半径**：当前无接线，生产进程和读者均为 0；将来接线时失败显式返回，影响调用者而非静默扩散。不访问用户数据、密钥、资金。上游文本是不可信内容，不是指令；调用者不得将其提升为系统指令。
- **取舍**：A 宽松兼容字段与直接透传，接入成本低，但有身份误判和私人字段泄漏风险；B 窄形状、显式错误、白名单投影，实现稍受限，未来协议变化需更新，回滚只需撤销新增文件。选 B。纯函数无法验证 endpoint 或真人归属，不声称解决该边界。
- **生效与重启**：当前未接入，单独提交无用户可见行为；接线后随宿主进程加载，需重启宿主，具体由组合交付确认。
- **验证**：纯 fixture 覆盖成功、未登录、游客、未知格式、空流、错误状态、无效 ID、数量上限与私人字段移除；错误均包含 code/error/hint。无网络、账号或真实浏览器调用。实际 self 格式、首页来源、界面错误展示和真人确认均待组合验证。
- **回滚与残余**：撤销本提交即可；组合代码如已依赖导出需同时回滚调用者。本层不代表观看、点赞或其他交互，不获取播放地址。
