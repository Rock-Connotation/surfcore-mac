# B站受控单轮：完整材料后点评与确认评分

## 完整逻辑

1. **链路**：宿主调用 `createBiliRoundService`，固定角色及 epoch 后以既有 feed 命令取候选；第一轮模型只能选择候选 BV。既有 debrief 提交感知作业，宿主轮询真实作业；完整覆盖与转写通过核验后，第二轮模型生成点评、评分和动态草稿，既有 score 命令写盘并回读，最后调用宿主记忆维护。调度、HTTP 和界面接线由集成会话负责。
2. **机制**：部分材料不能代表完整观看；因此检查角色、活动、BV、分 P、来源、覆盖和转写，任一不满足即停止，不调用点评模型或评分。模型流仅接受明确的 stop 终止与合法 JSON，限制输入、输出及两次调用，不提供工具，不重试。子进程以环境变量核验固定角色，避免角色切换导致写入新角色。
3. **影响面**：一个宿主作业最多两个模型流，可能产生模型费用，并写所选角色的评分与作业证据；不调用评论、点赞、动态发送、收藏或 QQ。既有同日同 BV 最高分语义保留；较低新评分保存在本轮点评，不能误报为已更新账本。额度、用量、模型或磁盘失败均返回 code 和 hint。
4. **取舍**：候选路线一是复用既有命令和共享感知服务，路线二是另建下载、模型及写盘编排。前者沿用现有凭据、媒体和评分边界，改动较少；后者重复状态和权限、回滚复杂。采用前者，新增服务只负责限定一次活动，取消时传播至感知作业。
5. **生效**：宿主需集成该服务和界面并重启后才使用新代码；本分支未更改运行中的 App，也未发布。宿主必须使用固定角色过滤作业状态与取消，并注入 B站范围上下文及同一感知实例。
6. **验证**：官方 App 随附 Node 24.21.0 执行 `ELECTRON_RUN_AS_NODE=1 '/Applications/DeepSeek Harness.app/Contents/MacOS/DeepSeek Harness' plugins/surfcore/scripts/test-bili-round.mjs`，退出 0；假模型、假命令和假感知覆盖完整链路、失败、取消、超时、切换角色、并发、重启及评分读写错误，不发外部请求。本分支此前 `npm run test:audit` 163/163、`npm run test:regressions` 和插件全套通过；最终组合及新增测试注册由集成会话复验。
7. **回滚与残余**：撤销本次七个文件并恢复备份 `_backups/2026-11-07-bili-round/` 中原文件即可回退；无自动重试。提交素材阶段限时 60 秒，取消会等待回执并取消已知作业；若超时，结果为未知，需在感知作业列表核对，不能保证底层作业已取消。模型服务忽略中止信号时，远端是否停止计费无法由本地保证；调用和输出上限不是金额上限。尚未使用真实账号、模型或官方 App 验收，路由、费用和真实内容效果需另行验证。

## 角色切换时的已提交作业（R3）

素材提交回执返回 ID 后、角色校验前可能切换角色。此时 debrief 保留 ID 并尝试取消该作业；返回 `STALE_CHARACTER`、作业 ID 及核对提示，取消失败标记为 unknown，避免误认为已经停止。实际 CLI 使用隔离假 Host 验证取消成功和失败两条路径，均无真实平台请求；单轮调用方也能取得该 ID 并执行自身清理。

定向测试通过 `import.meta.url` 定位命令入口；分别在仓库根目录和插件工作目录运行官方 Node 24 夹具，覆盖 `npm test --prefix plugins/surfcore` 的工作目录语义。
