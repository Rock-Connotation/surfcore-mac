# 抖音推荐：首次按键恢复与新回执停止

状态：导航专项及独立V2复审通过；最终组合/新候选实机待验。版本0.8.8不变。

## 完整逻辑

1. **链路**：Host严格首页service先验证self，再调用独立浏览器loadRecommendations；浏览器只监听固定self/tab/feed，service仍验证会话、序号、角色世代和前中后同账号。媒体UA仅在内部导航结果返回，公开metadata不带下载材料。
2. **机制**：真实页面初次按键有一次未切换，后续正常；另一次第5次切换才得到新feed。固定4次和过短稳定判据不能覆盖应用初始化/预取时序。导航采用最多8次已确认切换，共享一次初始丢键/迟引导恢复，最多9键；画面稳定1秒，已有新有效feed立即停止。回执在await间到达时也要在输入前复核，非切换错误不能被回执掩盖，关闭/超时先断言活动仍有效。
3. **影响面**：一独立浏览器/一个service读者，显式错误倍率1；不发平台互动、不调用模型。会读取已授权登录目录；原锁、未知退出和账号黏性保护不变。原始签名URL、正文和Cookie不写诊断输出。
4. **取舍**：A增加明确上限并按回执停止，能覆盖实测第5次才触发且减少无用翻页；成本是计数与一处内部回执，失败仍可见。B固定加长延时并继续固定4次，代码稍少但仍不能覆盖第5次且成功后仍翻页，未采用。初始最多一次恢复不扩展成全程重试。
5. **生效与重启**：更新插件Host后需重启独立DSH；已存在浏览器必须由原拥有者正常关闭，保留profile。新返回mediaUserAgent只取navigator的公开UA，不带授权头。
6. **验证**：`node plugins/surfcore/scripts/test-douyin-browser.mjs`通过。夹具覆盖初始丢键、8/9键上限、旧回执不停止新轮、await期间新回执阻止下一键、非切换键后收到回执仍成功、后续无回执失败停止、关闭/超时后零迟到按键及资料锁。独立审查V1复现回执交错P2，修正输入前/等待失败后复核，V2已关闭该P2，无新增确认P1/P2；另独立验证回执+超时/关闭不会恢复成功或迟到输入。真实200ms候选曾严格返回5项/5键；1秒候选首轮在导航前缺少新self回执而失败；随后45秒有界等待诊断中，真实严格service返回5项，仅3键且UA已取到，前中后self与固定源保持（未改变生产20秒默认等待）；不把下载诊断称新程序观看成功。
7. **回滚与残余**：回装上一包并关闭日常；保留新增账本与记忆。旧实现会恢复固定4键限制。最终新候选实装、视频/ASR/HY3和迁入结果见总case，不以专项通过替代组合验收。

## 失败可见

PAGE_NOT_READY、VIDEO_NOT_ADVANCED、验证/引导/未知退出继续返回code/error/hint。除首次明确丢键的一次恢复外，不对后续失败盲发按键；操作已关闭或超时，即使收到feed也不能恢复操作。界面提示检查独立浏览器后手动重试。
