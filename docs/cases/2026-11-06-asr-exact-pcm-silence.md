# ASR 全零 PCM 幻觉与确定性静音处理

## 现象与环境

官方 DSH App 0.2.2-rc.1 的隔离验收中，10 秒数字全零 PCM 被本地 whisper.cpp 转写成八段无中生有的文本，作业显示 `speech`。该问题由实际隔离作业 `d950145e-98db-460b-b227-87f475e9a81c` 证实；修复候选47e7e73已在官方App独立profile重新安装并实际复验，旧幻觉作业原样保留。

## 完整逻辑

1. **链路**：Host 共享感知服务验证音频与模型，FFprobe 探测后由 FFmpeg 规范化为 16 kHz、单声道、16 位 PCM WAV；`media.js` 检查数据并测量，`service.js` 形成区间覆盖和结果。渠道只消费结构化结果，不由此直接认定语音内容真实。
2. **机制**：旧流程虽然测量了全零，但仍先送 Whisper 推理；只有模型返回空文本才使用 `no_speech`，所以 Whisper 在绝对静音上生成的文本会变成 `speech`。新流程先严格验证 RIFF/WAVE 容器、完整数据长度和 PCM 格式，遍历全部 data 样本；仅当每个样本的整数值都为零时，跳过推理并返回空 segments 与 `EXACT_ZERO_PCM` 说明。任何非零样本，包括最小正负值，均继续正常推理；空、截断或不符合格式的数据报 `OUTPUT_INVALID` 和 hint，不视为静音。
3. **影响面**：所有共享 ASR 渠道受同一判定影响；不读取凭据、不修改原始音频、不触发云端或外发。全零只证明已取得 PCM 没有信号，不能证明未获取的源范围无语音；部分覆盖或来源时长未知仍为 `partial`、`unknown`。
4. **取舍**：方案 A 检查精确数值零，成本是遍历规范音频，判定确定且不会把低声信号当静音；方案 B 引入 VAD 和额外模型，能覆盖更多静音形式，但需要资产与准确率校验并存在误拒低声风险。选择 A，不设置音量阈值，不把空转写单独当静音。
5. **生效与重启**：实现位于共享媒体和 ASR 服务，需由主会话在隔离安装候选中重新加载 Host 才生效。缓存算法版本从 v2 改为 v3，使旧幻觉缓存与旧检查点不复用；原有作业历史与文件保留。
6. **验证**：`test-perception-silence.mjs` 使用官方 App 随附 Node 24 和隔离假 provider：全零实际不启动推理、正负最小非零样本仍调用推理、非零 metadata 不影响数据判断、空/畸形/截断/错误格式拒绝且 code/hint 非空、旧 v2 幻觉缓存不命中、部分覆盖保守为 unknown、取消后不写结果。另跑完整 service、资源和 Host API CLI 定向测试。主树官方Node24组合audit163/163、regressions和完整插件全部exit0，见 `_backups/20261106-macos-wp0/native-fixes/checks-20261106T152703Z/results.json`；官方App实际10秒全零作业 `0f1e8c0b-7f08-4e6f-b2b3-425706dc06e0` 为completed/no_speech、segments空、完整10000ms、EXACT_ZERO_PCM，且无推理转写文件；原生设置页提示可见。新包241秒非零音频、96秒真实无字幕B站音频均完整处理，后者末句与用户人工参考一致。原始结果位于本地验收目录 `native-47-{silence,long,bili}-result.json`。
7. **回滚与残余**：恢复旧 `media.js`、`service.js`、`util.js`，保留作业和样本；新版本缓存需隔离而不是删用户文件。全零不能代表低音量、背景噪声或一般静音检测，音轨截断、模型识别质量与其他架构仍需独立验证。
