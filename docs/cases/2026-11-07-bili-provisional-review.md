# B站部分材料的显式续评

## 完整逻辑

1. **链路**：既有单轮选定视频后等待共享 Host 感知；若作业为 partial，完整点评仍停止。用户明确选择续评后，`reviewPartial` 对同一作业重新读取 Host 结果和当前 B站角色上下文，至多调用一次原模型，保存部分点评及草稿，不执行评分或记忆维护。
2. **机制**：复核角色 epoch、活动、BV、分 P 和来源，要求无 ASR 错误且有语音转写。请求、获取、处理与缺失范围必须有效，处理与缺失共同覆盖请求范围，转写片段落在已处理范围。宿主独立生成范围和缺口说明，不依赖模型声称完整观看；只接受正常结束、用量已记账及不含分数的限定 JSON。原失败保留在 `lastFailure`。
3. **影响面**：仅显式同意、原选题已用一次模型且素材部分完成的作业可续评；额外最多一次原模型调用，可能产生费用。本次不提交新素材、不写正式评分、不发布或发送，已有感知观察经历不改写。
4. **取舍**：方案一复用原作业、共享感知和单轮槽；方案二放宽完整素材评分门槛或新建独立执行链。前者保留已选择证据和完整评分约束，回滚简单；后者容易把缺失内容当作完整观看并重复模型/媒体请求。选择前者。
5. **生效**：宿主需接入该方法、状态和范围提示，并重启以加载新代码。此分支未修改运行中的 App，未发布。
6. **验证**：隔离假模型与假 Host 夹具覆盖无同意、原完整路径拒绝 partial、有效续评、缺口及身份无效、空语音、ASR 错误、重复和并发、取消、切角色、历史作业与输出失败；断言不执行评分或维护。官方 App 随附 Node 24 分别从仓库根和插件目录运行 `test-bili-round.mjs`；组合 audit、回归、插件测试与原生 App 验收由集成会话执行。
7. **回滚与残余**：恢复 `_backups/2026-11-07-bili-partial-review/` 原服务和测试即可；作业记录中的部分点评仍是用户数据，回滚不删除。服务无法保证忽略中止信号的远端模型立即停止计费，token 上限不是金额上限。未发真实模型或账号请求，真实模型输出、路由和界面仍待用户授权后的验证。

## 发布交接块

- 变化：用户显式同意后可对已选视频的已处理片段生成带缺口说明的临时点评和草稿；不产生正式评分。
- 范围：既有单轮和共享感知，完整点评仍要求完整素材。
- 验证：隔离行为夹具通过；最终组合门禁及真实 App/模型验收待集成。

- 回滚：恢复服务和测试备份，保留用户数据；未提交、未改版本、未发布。
