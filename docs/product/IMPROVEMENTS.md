## A1 定位漂移：三套叙事同时存在 → 已拍板，入口文档改写待执行

**拍板（2026-11-12）**：核心是**数字角色分身**，通过 QQ、B站、抖音等多平台渠道和人互动、替人做事；**渠道是出口，不是产品本体**。PRD v0.2 已按此重写定位、用户、边界、优先级章节。

**残留待办（不在本批做，列清楚给后续批次）**
- 根 `README.md` 开头仍是"数字角色运行环境"叙事混合；需按 §1.1 一句话重写首段。
- `plugins/surfcore/README.md:1-10` 仍是"QQ × B站 合体插件"口径；需改写并同步"默认只开 QQ"。
- `ROADMAP.md` 顶部加"范围闸"：新功能必须回答"服务身份连续性/长期关系/多出口生活中的哪一条"，否则不进 dev；不在叙事内的渠道（贴吧、微博、直播间）默认 P2。
- 商业化/付费/额度变现类表述：全仓库排查后仅在 PRD 待确认清单出现过一处，已随拍板删除；额度按"资源约束"表述（PRD §4.2 I）。

**验证**：三份入口文档首段能用同一句话概括；`grep -rn "合体插件\|Windows 优先" README.md plugins/surfcore/README.md docs/` 零命中。

## A5 新用户激活路径过长

（v0.1 评估维持不变。）

**现象**：装 DSH（可能要打 app.asar 补丁）→ SnowLuma → 语音引擎/火山凭据 → 桌宠 Electron → 抖音浏览器 profile → B站扫码，六步外部依赖，任何一步失败都表现为"功能不存在"。

**与拍板的关系**：默认入口收敛为 QQ（拍板 3）会**缩短**第一段激活路径（装完即用 QQ），但 B站/抖音开启步骤仍在。首启向导（doctor 结果前置、依赖检测、不做自动安装）建议维持，排 P1。

**验证**：全新环境启动后，概览页能列出"缺 N 项，分别影响哪些功能"，每项有操作按钮/命令。

## A7 设置窗口与新增能力不同步

（v0.1 评估维持，补充拍板核查结论。）

**拍板核查（2026-11-12）**：设置窗口**无按用户类型的分叉**（见 A4）；"所有功能对所有用户可用"意味着 A7 的解法不是"按用户露出"，而是**给所有用户补齐只读状态卡**（任务 Harness 开没开、Memory V2 当前 backend、抖音/桌宠当前开关）——这与拍板一致且更简单。

**建议**：先做只读状态卡；`config.example.json` 补 `chat`/`pet`/`tokenBudget`/`platforms.start` 模板值。

**验证**：窗口内能回答"任务 Harness 现在开没开、Memory V2 走哪个 backend"。

## 不建议做的事（避免把问题变成新问题）

1. **不要为了"统一"重写桥接**：18k 行里混着真实事故修复；先护栏、后抽取。
2. **不要在 V2 转正前删 V1**：QQ V2 回复链路依赖 Memory 路由 v2（`qq-v2-reply-host.mjs:42`）；先转正、后退役。
3. **不要用自动安装解决 A5**：违反"不代用户操作/不绕过平台"的边界，且引入新的权限面。
4. **不要把文档数字手工再抄一遍**：A3 的根因是手抄，不是数字错。
5. **不要给桌宠/抖音排新工时**：拍板已定优先级（降级/暂缓），投入前需用户重新拍板。
