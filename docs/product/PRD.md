## 一、产品定位

### 1.1 一句话（已拍板）

**SurfCore 的核心是「数字角色分身」：一个单机运行的、有统一人格、会遗忘的记忆、自己作息的数字角色；QQ / B站 / 抖音 / 桌宠等都是这个分身和人互动、替人做事的出口。渠道是出口，不是产品本体。**

- 这不是"把大模型接进 QQ"的机器人框架，也不是"QQ×B站 合体插件"。仓库自己的表述是"给模型一个身份、一套会遗忘的记忆、一份作息、两只手和一个能坐在你桌面上的分身"（`README.md:4-6`）；v0.1 扫描把它概括为"数字角色运行环境"，v0.2 按拍板收束为：**核心是分身，渠道是出口**。
- 任何新功能必须回答"它让这个分身在哪个出口上更像她自己、更能替人做事"，否则不进范围（见 §五 优先级与 IMPROVEMENTS A1 的范围闸）。

### 1.2 它由什么组成

| 组成 | 形态 | 作用 |
| --- | --- | --- |
| 角色本体（人格 + 记忆 + 作息 + 目的） | 插件内身份层 / 记忆层 / 主动目的 | 分身的"她自己"；跨出口共享同一套 |
| `surfcore` DSH 插件 | DSH 宿主进程内的 bundle | 设置窗口、B站调度、记忆卡维护、桌宠 API、token 采集 |
| QQ 桥接 | 独立 Node 进程 `src/bridge.js` | QQ 出口：收发、会话映射、工具面、控制台 `:3100`、安全闸门 |
| 渠道适配 | 插件内 `lib/` + `tools/` | B站（HTTP + 浏览器扫码）、抖音（独立浏览器 profile）、桌宠（本地令牌 HTTP） |
| 外部依赖 | 用户自行安装 | SnowLuma（QQ 运行时）、语音引擎、桌宠 Electron 工程、DSH 本体 |

### 1.3 它解决的三类问题

1. **身份连续性**：同一个角色在 QQ、B站、抖音、桌宠里是同一套人格与记忆，而不是四个各自为政的 bot。
   - 依据：`src/character-persona.js`、`src/memory-card.js`、`RULES.md:51-66` 的三层提示词。
2. **长期关系**：记忆会衰减、会遗忘、有"最初"和"初次相遇"，主动机制会从记忆里提炼目的来找人。
   - 依据：`docs/guides/MEMORY_CARD.md`、`src/purpose-engine.js`。
3. **多出口生活**：在 QQ 里像群友、在 B站/抖音里像用户，有作息、额度、偏好和风控边界。
   - 依据：`lib/scheduler.js`、`lib/douyin-*.mjs`、`docs/guides/CHANNEL-STATUS-2026-11-07.md`。
   - 边界提醒：出口是可选项不是本体——QQ 是默认出口（见 §二），其余出口由用户在设置中自行开启。

### 1.4 它明确不是什么（边界，已拍板）

| 不做 | 依据 |
| --- | --- |
| 不代用户登录 / 扫码 / 绕过平台风控 | `README.md:89-90`、`BOUNDARIES.md:158-166` |
| 不打包、不分发 SnowLuma（第三方专有运行时） | `README.md:107-108`、`BOUNDARIES.md:18` |
| 不做多用户 / 多租户 / 远程管理控制台 | `BOUNDARIES.md:23-24` |
| 不做不可逆删除（清理先隔离） | `AGENTS.md` 铁律 6、`ROADMAP.md:81` |
| 不把私信 / 密钥 / 联系方式跨平台搬运 | `plugins/surfcore/README.md:221-237` |
| 微博明确不做；贴吧仅预留 | `platforms/README.md`、`platforms/tieba/manifest.json` |
| **不做商业化**：无付费、无订阅、无额度变现设想；额度与成本控制按"资源约束"存在（防止模型花费失控），不是商业功能 | 2026-11-12 拍板 6 |

**平台承诺（已拍板，2026-11-12）**：**Windows 与 macOS 是双平台一等公民**，同等对待、同等验收；Linux 维持"未验证"，不承诺。旧文档里"Windows 优先 / 不支持 macOS"的表述已按事实修正（见 IMPROVEMENTS A2）。

## 二、目标用户

### 2.1 主要用户（已拍板收敛）

| 用户 | 特征 | 依据 |
| --- | --- | --- |
| 仓库主人（唯一真实用户） | 单人开发、单人使用；自己装 DSH + SnowLuma + 语音引擎，愿意按文档排查；**不找志愿者，不做规模化用户假设** | 2026-11-12 拍板；`README.md:42-55`、`BOUNDARIES.md:158-166` |
| "想要一个有身份的角色"而不是"一个问答窗口"的使用者 | 关注人格、记忆、主动搭话 | `README.md:74-90` |

**用户分级（已拍板，2026-11-12）：不存在"高级用户 / 普通用户"之分。所有功能对所有用户可用；所有用户的设置窗口完全一致，不按用户类型分叉配置面。** 代码核查结论：设置窗口 15 个标签为静态渲染（`plugins/surfcore/lib/client.js:6938-6954` 定义、`:7215` `TABS.map` 无条件渲染），不存在 advanced toggle、隐藏标签或 feature flag 控制用户可见性的分叉——现状已符合拍板，无需改代码。

### 2.2 非目标用户

- 想开箱即用、不愿装第三方运行时的用户（SnowLuma / 语音引擎 / 桌宠均为外部依赖）。
- 需要多用户 SaaS、团队协作、远程托管的用户。
- 只想要"API 网关"或"群管理机器人"的用户（本产品不做禁言/踢人/文件管理等管理动作，`RULES.md:38`）。

### 2.3 默认体验（已拍板）

**默认入口是 QQ**：安装后 / 首次打开默认落在 QQ。B站、抖音等其他出口由用户在设置中自行开启处理。

- 现状差距：当前新装默认 QQ+B站 都开（`plugins/surfcore/README.md:36`），与拍板不一致；改为"默认只开 QQ"涉及默认配置 + 老用户配置迁移（不能静默关掉已开的 B站），已立为待办批次，见 §七。

## 三、产品原则（从现有硬规则 + 拍板提炼）

这些不是新主张，而是仓库已经在执行的约束；PRD 后续功能都受它们约束。

| 原则 | 含义 | 依据 |
| --- | --- | --- |
| 分身是本体，渠道是出口 | 新功能先服务身份连续性/长期关系/多出口生活之一，否则不进 dev | §1.1 拍板、IMPROVEMENTS A1 |
| 硬边界优先于提示词 | 工具面、白名单、审计是边界；正则与人格提示只是启发式 | `BOUNDARIES.md:110-126` |
| 失败必须可见且可行动 | `ok:false` 要带 `code` / `error` / `hint`，前端必须展示 | `AGENTS.md` 1.7、`docs/guides/ERROR-REPORTING.md` |
| 单一真相 | 三份配置各归其主；额度只有一个入口；角色包整包切换 | `ARCHITECTURE.md:238-249`、`plugins/surfcore/README.md:209-217` |
| 可回滚 | 删除先隔离；发布走 git 对象；main/dev 分离 | `AGENTS.md` 1.5/1.8、`ROADMAP.md:81` |
| 默认保守 | 默认只开 QQ；扩展默认关、跨平台记忆默认关、直播间默认关、语音默认关 | §2.3 拍板、`BOUNDARIES.md:56` |
| 资源约束而非商业功能 | 额度/成本控制的目标是"不失控"，不做任何变现设计 | §1.4 拍板 6 |

## 四、功能架构（用户视角）

### 4.1 模块总览

```
身份层   角色（人格卡 / 角色包 / 切换与快照）
记忆层   衰减记忆卡 · 全量卡 · 双向脱敏同步 · 身份对齐 · Memory V2（后端已 V2-only，见 2026-11-12 退役 case）
表达层   QQ（默认出口）· B站 · 抖音（暂缓）· 桌宠（低优先）· 语音 · 主动目的
约束层   白名单/黑名单 · 工具守卫 · 鱼群保护 · 额度 · 隐私闸 · 身份闸
运维层   设置窗口（15 标签，全用户一致）· 桥接控制台 · 诊断/备份/更新 · 扩展与平台接口
```

## 五、功能优先级（按拍板重排）

优先级依据：ROADMAP 的 M1–M6、AGENTS 测试与发布纪律，加上 2026-11-12 的六条拍板（定位、双平台、默认 QQ、无用户分级、桌宠降级、无商业化）与同日四条补充（抖音暂缓、火山 TTS 第一梯队、单人开发）。

### P0（不满足就不能称为可用）

1. **QQ 消息闭环**：真机发消息 → DSH 会话 → 回复回到 QQ（M1）。**QQ 是默认出口**。
2. **安全边界**：群友无本地工具、发送白名单、回复审计（M2）。
3. **记忆与配置不丢**：清理可回滚（M4）。
4. **失败可见**：所有用户动作失败时有 `code/error/hint` 且界面展示（AGENTS 1.7；lint 门禁已上线）。
5. **门禁通过**：`npm run test:audit`、协议回归、插件测试（AGENTS 铁律 5）。
6. **设置一致性**：所有用户看到同一个设置窗口，无按用户类型的分叉（现状已满足，防回潮）。
7. **默认只开 QQ**（待实施：改默认值 + 老用户迁移，见 §七）。

### P1（核心体验）

8. 角色/人格/记忆的一致性（同一角色跨各出口）。
9. B站自主生活（作息、选题、评论、鱼群、分享）稳定可关——用户在设置中开启后即属核心体验。
10. **语音**：至少语音库 + 一种 TTS 路由可用；**火山 TTS 真实计费与音质验收排第一梯队**。
11. 设置窗口与诊断能覆盖新增能力（不能"代码有、界面没有"）。

### P2（增强与退役；均不阻塞核心）

12. Memory V2 / B站 V2 / QQ V2 从 dev 转正；**V1 系列退役进行中，仍有残留且测试未通过**——退役清单与逐项状态见 [V1-INVENTORY.md](V1-INVENTORY.md)，操作记录见 [docs/cases/2026-11-12-v1-retirement.md](../cases/2026-11-12-v1-retirement.md)；`~/.dsh` 用户数据只读不动，代码残留与旧配置手工改值见该清单 §1/§4。
13. 任务 Harness 与 Mac 本地执行的产品化（准入、产物、回执、可见状态）。
14. 新平台（贴吧）与真实扩展。

### ⏸️ 暂缓 / ⬇️ 降级（拍板明确不投入）

- **抖音**：先不管。代码保留不动，稳定性验证与新能力不排期；用户可在设置中自行开启使用。
- **桌宠**：优先级较低。已实现能力保留（安装/对话/气泡/专注模式），ASR 等增强不排期；不出现在主推能力里。

> 依据说明：P0 来自 ROADMAP M1–M6 + 拍板；P1 来自 README 能力叙事与实际模块 + 拍板（火山 TTS）；P2 的排序依据是"代码已在 dev 但未发布/未默认启用"。单人开发，无用户访谈数据。
