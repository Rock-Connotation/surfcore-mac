# QQ V2 private Native syntax ledger

`createQQV2NativeLedger({ nativeCodec, corePersona, toolSpecs, validateOwnedToolContext })` returns a Host-private, ephemeral ordered message ledger. It proves only that the Native model input matches its previously observed message and tool-result syntax. It is **not** Kernel source binding, a receipt, ACL, platform identity, network admission, or permission to send. The future QQ Source authority must independently bind every actual source and output to Kernel receipts and apply current actor, role, route and audience policy. The fixture's source binding is deliberately false.

The trusted Host supplies one fixed persona, Native codecs, fixed typed tool specs and the private owner context checker. `seed({sessionId, requestId, content})` accepts one Host-composed text-only user message and pins expected Native system and `user-rpc` messages. Seed content is not independently authenticated by this ledger. The Host must never pass model-controlled callbacks, codec implementations or tool specifications.

`validateInput({options, request, preparedConfig})` checks the complete ordered Native messages against the ledger, pins unique actual message IDs when first observed, and rejects later ID changes, unknown fields, hidden/non-enumerable or symbol fields, opaque objects, images and files. It matches `request.sessionId` and the owner's exact SHA-256 over `JSON.stringify({messages,toolHistory,tools})`. Only provider, model, maxTokens and reasoningEffort config fields are accepted; their actual options values must equal the original prepared configuration. Provider and model use the shared Core route validator: nonempty, trimmed strings of at most 512 JavaScript UTF-16 code units without ASCII control characters, including valid Unicode, spaces and punctuation. Actual Native tool schemas must exactly equal the fixed Host schemas compiled to the installed `defineTool` parameter shape; unknown tools, schema changes and history updates are denied. History may have no tools or the exact fixed schema set. Each admitted options object is bound to its original request and configuration identities.

Fixed specs use the Native parameter authoring shape: required/optional strings with optional enum, booleans, finite bounded numbers, safe integers, and arrays of at most 128 strings. String arguments are limited to 64 KiB. Optional parameter descriptions are supported. Object, file, attachment and other schema types are rejected rather than interpreted. Tool argument objects may contain only declared keys and must contain every required key; duplicate JSON keys, wrong types, unknown enum values and excessive bounds are rejected. This is a deliberately narrow subset; adding more types requires an explicit contract change.

`captureModelOutput({options, request, preparedConfig, dispatchId, phase, chunk, signal})` permits `start` before validation because the owner observes start before budget preparation, but no chunk or completion is accepted until the exact tuple has passed `validateInput`. Actual Native accumulator and assembler instances process chunks. Only known text, reasoning, tool-call, usage and finish shapes are accepted, and chunk hashes are rechecked before commit. A successful `complete` requires a normal `stop` or `tool-calls` finish and commits the assembled assistant message and unique ordered tool-call IDs, names and arguments. Failed, cancelled, early-returned, truncated or malformed streams commit nothing. Each dispatch ID and options object is single-use. Block indices follow the Native SDK nonnegative safe-integer rule, excluding negative zero; its accumulator and assembler use encountered-entry arrays and maps, so sparse numeric indices do not imply sparse-array allocation.

`captureToolResult({execution, content, isError})` requires the private owner context check and the next unconsumed, actually observed call ID, name and arguments to agree. It appends the Native text-only result exactly once, in observed call order. The context check is a guard witness, not an unforgeable SDK proof; trusted Host-owned fixed tool callbacks must also bind these calls and results to their independent Kernel receipts. A context witness or matching syntax never supplies authority on its own.

The ledger limits expected messages to 1,024, fixed tools to 32, each observed stream to 4,096 chunks and 8 MiB, and each complete input to 4 MiB. JSON-shaped data has depth/node bounds; proxies, accessors, cyclic values and unsupported prototypes fail closed. Public operations return `{ok:false, code, error, hint}` on denial; construction throws the same structured fields when dependencies or fixed specs are unsupported. `getStatus()` exposes counts and retirement state only. `retire()` drops ledger state and makes further operations fail. It neither persists data nor integrates QQ Source, Bridge or sends.
