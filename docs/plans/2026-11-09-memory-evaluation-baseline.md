## 13 类设计场景的覆盖层级

JSON 的 `scenarios` 覆盖设计的 13 类：延迟/缺事件；时间/承诺；身份/绑定；私密 canary；媒体/归属；玩笑/假设/注入；超时/配额/写故障/取消及 usage unknown；角色/会话撤销；万级事件/长期量；重置/抑制/纠正/删除/spool replay/旧备份恢复；中断迁移/未知 ACL；可选后端缺失；固定数据和预算对照。

每项均标明 `scenario_metadata_only_not_production_test`。其中四个私密 canary、删除/抑制/旧恢复/重放样本、另一角色、未知 ACL 隔离及 usage unknown 有实际源事件或结构化元数据；这为后续故障注入提供输入，**数据存在不证明这些运行时行为已经实现**。当前没有在 query / before-model / during-generation / before-send 四阶段撤权，也没有执行故障恢复、备份恢复、spool 重放、身份绑定或 usage 账务操作。

## V1 执行链与适配假设

1. `src/memory-card.js` 的真实 `addMemoryRecord()` 逐条接收合成事件，使用真实打分/脱敏/去重及 `maxRecords:600`。未使用 pin/owner/答案标签偏置。
2. 每次成功返回的 legacy record 在热卡淘汰前都写入 `memory-card-full.jsonl`，因此全量归档确实保留 10,000 条。热卡分别为主角色 600、另一角色 1 条，总共 601；不能把第二角色混入主角色计数。
3. 这是一对一投影的基线 fixture，**不是** `maintainMemoryCard()` 或完整摄取链路集成测试。真实长期记忆的人工重要度、已有钉选、衰减状态、历史维护时机不由本语料模拟。V1 无此处生命周期覆盖，原始删除/抑制/隔离样本保留在 legacy 投影中，不伪造过滤能力。
4. 全量诊断直接调用导出的 `recallFullMemory(paths, query, {limit:8,maxScanBytes:209715200})`。主/副角色归档分开；总 archive 10,707,892 字节，低于扫描上限，旧针实际被扫描到。
5. 自动上下文直接调用导出的 `buildCharacterContext()`，显式固定角色与 epoch 1，`allowStale:true` 用于隔离 fixture。读取路径为本次 `_backups/memory-v2-evaluation/v1-*/synthetic-home` 内的角色 memory，`DSH_HOME` 在动态 import 前设置，并断言实际导出路径匹配。没有操作真实 profile 或当前角色。
6. 自动请求仅启用 memory，预算 1,800 字符，total 6,000 字符；不传检索问题。源码调用 `renderMemoryCard()`，按既有分区/重要度/最近性挑选。固定 `Date.now` 并在 finally 恢复，避免相同语料随运行日变动。
7. 自动路径没有 source-ID receipt，因此从渲染列表行中精确匹配完整 record 文本，保守重建来源，按输出顺序取前 8 个独立来源。过长/被缩写正文可能无法重建，不能把这个代理称作生产 provenance。当前表中的“自动”均指此来源覆盖代理。

`recallFullMemory()` 只有字面查询词匹配，没有 audience 参数；不能把它描述为自动热提示的查询搜索。`v1QueryTokens()` 仅镜像已有分词规则来断言零重合标签，从不向索引加入同义词。后续可复用 `loadFixture/validateFixture/partitionFixture/measureCandidates/summarizeMetrics/latencyStats/projectLegacyInput`，导入这些函数不会运行基线或修改环境。没有预设尚不存在的 V2 API。

## 指标定义与实测

`Hit@8` / 此处的 summary source Hit@8：前 8 个来源中至少有一个问题正确来源。`completeEvidenceAt8`：前 8 中包含某个完整必要来源集合。两个指标只以 130 个可回答问题为分母；时间双来源问题需要两条同时进入完整集合。它们衡量来源召回，不评分答案是否尊重时间/归属/否定。

| 测量 | 全量 V1 诊断 | 自动 V1 热卡覆盖代理 |
| --- | ---: | ---: |
| 全部可回答 Hit@8 | 118/130 = 90.77% | 5/130 = 3.85% |
| 完整必要来源集合 | 118/130 = 90.77% | 5/130 = 3.85% |
| 开发可回答 | 58/64 = 90.63% | 2/64 = 3.13% |
| 留出可回答 | 60/66 = 90.91% | 3/66 = 4.55% |
| 延迟/改写 | 48/60 = 80% | 0/60 |
| 有意义词重合改写 | 48/48 | 0/48 |
| 零查询词重合改写 | 0/12 | 0/12 |
| 时间版本/承诺 | 30/30 | 0/30 |
| 身份组可回答部分 | 15/15 | 5/15 |
| 自身经历/归属 | 25/25 | 0/25 |
| 未知问题返回零候选 | 0/30 | 0/30 |
| 原始禁止来源候选 / 涉及问题 | 99 / 22 | 3 / 3 |

禁止来源判据包含问题显式禁止来源、错误角色、错误 ACL 域、删除/抑制/隔离状态。自动路径的三条均为身份问题声明禁止的来源（`fixture-query-093/095/098`），不是认定已发生了跨 ACL 的发送泄露。四条私密 canary 都可用 audience-less 全量诊断找回；该接口是诊断/管理侧读取，这不证明平台发送泄露，也不证明生产隔离通过。

老针 `fixture-event-00001`：归档存在，热卡不存在；诊断前 8 命中，自动前 8 未命中。所有未知问题有候选只说明词面相关片段仍可能出现，**不等于生成模型编造了答案**。

生成答案支持率、无支持陈述/幻觉率、无答案克制率全部输出 `null`（未测）。没有模型生成就没有这些指标的分子/分母，也没有“>=95% 已通过”的结论。设计建议的改写 Hit@8 >=80%、支持率 >=95%、无答案克制率 >=95% 仅作为 proposal 元数据保留；诊断在此固定配比上达到 80% 不是自动路径、V2 或整体质量验收。

## 取舍、回滚与交接

选择静态 JSON 而非运行时生成器，成本是约 5.8 MB 文本，收益是每条源事件/答案可审计、旧针和规模可物理验证、没有 seed/时间漂移。选择真实导出 V1 函数而非自写检索器，成本是一次较慢的投影和全量扫描，收益是暴露真实字面召回与自动热卡差异。

三份新文件只提供离线评测，不改变服务行为、不需要重启。回滚可由父会话隔离这三份新文件，保留 `_backups/memory-v2-evaluation` 证据；不涉及运行时数据迁移。没有提交、依赖安装、网络、平台发送或服务/profile 修改。可见 UI 没有变化，不适用 before/after 截图。

父会话应独立复核固定语料、分母、导出 V1 调用和报告，另将所需 case/发布交接汇总到其自有文档边界。本子任务只获准编辑指定三份文件，未扩大到 `docs/cases`、ROADMAP、COORDINATION 或生产模块。尚未验证的生产 ACL、角色/会话撤销、故障/删除恢复、真实 usage 记账和模型答案质量交给对应运行时验收；这套数据不替它们背书。
