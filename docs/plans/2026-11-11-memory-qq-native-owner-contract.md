# QQ V2 private Native owner contract

This is an ownership and admission capability, not QQ bridge integration or proof of message provenance. V1 and the existing remote QQ path are unchanged. A trusted Host must retain this module's private return value; public JSON, session IDs, preset names and provider wrappers cannot create ownership. `getSessionMemorySafety` says only that this owner still controls its actual private agent and its current role, route, preset and tool definitions. It does **not** approve a QQ message, conversation, actor, source, destination or send.

`createQQV2NativeOwner({ nativeModules, llm, getLlmHookContext, corePersona, tools, tokenBudget, getCharacter, provider, model, estimatedTokens, priceSnapshot?, sourceAuthority, onAgentError? })` asynchronously creates a separate `createIsolatedNativeRoot` and one internally named agent with an exact provider/model and role/epoch. All parameters come from a trusted Host. The LLM and context are the real owning Native facade/context; the provider is selected explicitly. `estimatedTokens` is a positive conservative per-call estimate. `priceSnapshot`, if present, is a cloneable trusted Host price snapshot consumed by the existing budget service; that service decides whether the price is sufficient for configured limits. A bad or absent usable price can deny inference rather than bypass a currency limit.

The private return value exposes `sessionId`, `preset`, `providerRouteId`, `getSessionMemorySafety({ sessionId, preset })`, `followup(message)`, `whenIdle()`, `getStatus()` and `retire()`. The session and preset must match the retained actual agent and private Native registry. The Host must not expose this object or a way to supply its dependencies to untrusted callers. Source admission is still required for every `followup` and every model step; it is not implied by safety being true.

Each actual Native `llm/stream` callback checks the root's private async-local original request and agent, the SDK request brand, actual session and selected route, current role/epoch, private preset, complete live registered definitions (including callback identities) and the actual model-facing tool schemas. The owner snapshots its input digest, sends the actual request through `createAgentBudgetMiddleware`, and repeats owner, input, route, role and tool checks during source preparation, validation, and immediately before the serialized first provider dispatch. The root's additional Native tool guard rechecks the same live ownership and permits only exact approved definitions. Malformed tool lists are rejected with a structured error. Live role and Native inspection failures return a fixed `QQ_NATIVE_SESSION_UNSAFE` error; the safety predicate returns false. Resolved execute, render and other tool callbacks are pinned even when inherited from a prototype. Owned tool definitions and their callback closures are trusted Host code; changes to external state captured by a trusted closure cannot be detected here.

The `sourceAuthority` is an independent trusted Host capability, not a client assertion. It provides `prepareInput({ options, request, signal }) -> { ok: true, handle }`, `validate({ options, request, handle, phase, signal, ... }) -> true | { ok: true }`, and `admitNetwork({ options, request, handle, signal, dispatch })`, which must serialize and revalidate the underlying grants and invoke/return `dispatch()` exactly once when permitted. It must validate the complete real Native messages, tool history, attachment/content, every actor and their current source permissions; it must own, revoke and release any prepared handles and account for outputs needed as future input. A fixture returning true establishes none of these source facts. Never pass client-provided `true`, a metadata-only check or a post-submit observer as this authority.

`retire()` immediately blocks admission and aborts its work; it awaits root cleanup and acknowledges only `retired: true` with `pendingCleanup: 0`. Failed cleanup retains the original root for `retire()` retry; a root-initialization failure may carry a non-enumerable `retryCleanup` capability that the caller must retain and retry. This is a process-owned capability: durable cross-restart retirement barriers and actual QQ session integration remain Host responsibilities.

Ordinary tests use mock Native primitives to exercise denial, pricing snapshot, input change, malformed dependencies, inspection failures, inherited callback mutation and failed-cleanup retry. Parent independently reviewed run2 and ran all 16 ordinary scenarios plus the isolated installed-SDK fixture against the final production/test hashes. Native verification recorded 1 fake provider call/15 tokens, 1 serialized gate, 2 hook registrations/removals, actual owned request/route/role/scoped-tool/source-denial/budget fences and acknowledged unload, with no external attempts. Evidence: `_backups/memory-v2-coordinator/qq-native-owner-independent/verification.json`. Actual QQ source authority, bridge/session routing, multi-actor/group/private ACLs, sends, restart recovery and production integration remain unverified.

## Private output and tool context observation

An optional trusted `sourceAuthority.captureModelOutput({ options, request, preparedConfig, dispatchId, phase, chunk?, signal })` receives the actual branded Native request as `options`, the existing admission DTO as `request`, and the original Native prepared configuration by identity. The same references and unique dispatch ID apply throughout a dispatch. The owner locks inspectable plain prepared-config objects recursively and compares them with an independent snapshot before and after source work and immediately before dispatch; opaque, proxy or accessor-bearing configurations are denied. Native's installed `prepareCall` already deep-freezes its configuration. A successful observation must return `true` or `{ok:true}`. Phases are `start`, one `chunk` per actual stream chunk before yielding it, and `complete` only at normal exhaustion. Denial, exception or mutation prevents the affected chunk from escaping and becomes `QQ_NATIVE_OUTPUT_UNPROVEN` with a fixed error and hint. Throw, cancellation and early iterator return produce one `failed` callback instead of `complete`; failure observation checks the retained actual call identity even if input validation has failed. This callback is optional only for compatibility with the pre-existing owner capability; a future source authority must require it and independently own its source ledger. The owner does not retain model output for replay.

The owner's synchronous `validateOwnedToolContext(execution)` returns `{ok:true}` only when the same object was seen by its private Native `tools.guard` and still matches the retained agent, pinned definition, name, call ID, token, tool-set identity and original arguments. Denial returns `QQ_NATIVE_TOOL_EXECUTION_UNPROVEN` with error and hint, and invalidates an existing witness. The check fails after retirement. **This is not an SDK-branded, unforgeable execution proof**: privileged Host code can call the SDK's public `checkGuards(copy)` to produce a guard witness for a copy. The trust boundary is the fixed Host-owned pinned typed callbacks and actual SDK; untrusted model data and ordinary clients must never receive the root, execution object or registry. A future Source factory must own those callbacks and independently match real observed model tool-call IDs and arguments to Kernel-bound source receipts. This context check alone is never source, ACL, send or network authority.

When output observation is enabled, retirement first requests actual agent cancellation and waits for the active agent to become idle before closing the isolated root, so in-flight iterator cleanup can report failure while the owner is still retained. Only root cleanup's acknowledged result marks retirement complete; failed retirement remains retryable. This milestone does not wire QQ Source, QQ Bridge or platform sends and does not prove source provenance.
