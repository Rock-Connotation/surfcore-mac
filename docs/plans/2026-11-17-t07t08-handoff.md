## T07：用真实 DSH 工具复验（约 5 分钟）

准备：一个**专门**的测试目录（不要用任何真实项目目录）。

```bash
mkdir -p ~/Daily/tmp/local-task-acceptance
printf '纪要一：本周完成 A、B\n' > ~/Daily/tmp/local-task-acceptance/note-a.txt
printf '纪要二：下周计划 C\n'     > ~/Daily/tmp/local-task-acceptance/note-b.txt
```

1. 重启 DSH（菜单退出后重新打开），确认插件加载：`DSH 设置 → SurfCore` 能看到「本机任务」标签。
2. 让桥接重新读发现文件：设置页「QQ」→ 重启桥接（或退出重启 DSH）。
3. 在 QQ 主人私聊里按顺序发这三条，逐条等回执：
   - `本机任务：列出 ~/Daily/tmp/local-task-acceptance 下的文件`
   - `本机任务：读出 note-a.txt 的内容`
   - `本机任务：新建 out.txt，写入「验收通过」`
4. 复验"只新建不覆盖"：把第 3 条**再发一次**（新消息 → 新任务），预期回执是失败而不是覆盖，
   并且 `out.txt` 内容不变（`cat` 前后一致）。
5. 自然语言汇总：`本机任务：读 note-a.txt 和 note-b.txt，把它们合成一份周报写到 weekly.md`
   - 预期：`~/Daily/tmp/local-task-acceptance/weekly.md` 新出现且包含两份纪要的要点；
   - QQ 里收到一条完成回执，内容包含产物位置。
6. 记证据：`ls -l` 前后快照 + 每条 QQ 回执截图 + 设置页任务列表截图。

判据：工具调用失败必须在 QQ 里看得见（不是只写日志）；文件内容与预期逐字一致；
`out.txt` 那一步必须是"失败 + 原文件未变"，否则 T03 的只新建担保没落地。
